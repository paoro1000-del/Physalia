# AIディセプション手法の多角評価

## 既存手法との関係と新規性

2026-10-28時点の公開文献・ツールを対象とした初期調査では、主要な発想の多くに先行例がある。2026-10-30にRouxiiのプレプリントを追加確認した。以下の「近い」は原理が共通するという意味であり、機能や実装が同一という意味ではない。「同一例未確認」は限定的な調査で見つからなかっただけで、新規性や特許取得可能性を意味しない。

| 本企画の名称 | 先行例との関係 |
|---|---|
| スタティック・デコイ・エンドポイント／カナリア・トークン／コンフィグ・ファイル・トラップ | 偽のネットワーク資源、ファイル、認証情報による検知は既知。[MITRE D3FEND](https://d3fend.mitre.org/)にデコイファイル等が整理されている。具体的な.envへの配置と通知基盤は方式ごとに異なる。 |

| アテンション・デッドロック／ゴール・ハイジャック | AIエージェントのループや誘導は研究例がある。[Cloak, Honey, Trap](https://www.usenix.org/conference/usenixsecurity25/presentation/ayzenshteyn)はCTF環境でループ等を扱うが、多くはプロンプト注入を必要とせず、本案と同一のプロンプトや効果を示すものではない。 |
| エンクリプテッド・ディープ・ネスト | 暗号化と偽データを用いた欺瞞は既知だが、上記ハニーボルトは誤った鍵で偽候補を生成する別方式である。複数の暗号化階層で探索を遅らせる本案と同一の防御設計は、この初期調査では確認していない。 |
| エンコーディング・メイズ／コンテント・レングス・カモフラージュ | 複数の表現やHTTP応答を使う一般的発想はあるが、本設計と同一の防御手法・有効性はこの初期調査では確認していない。後者は本企画では不採用。 |

したがって、企画の差別化は「すべて初めての原理」と主張するより、複数の既知手法の組み合わせ、導入・隔離・運用のしやすさ、攻撃者が本物を識別できない状況の設計、公開できる検証結果に求める。学術上の新規性、特許の新規性・進歩性、他者の権利を侵害せず実装できるかは別問題である。判断には具体的な実装を特定し、論文・製品・特許を対象国・期間を定めて調査し、必要に応じて専門家に相談する。

## 結論と判断の範囲

**ディセプション全体には価値がある。カナリアによる検知に加え、探索の迷走・予算消費が期待できる手法も採用する。** ただし「時間を使わせた」ことと「実際の秘密情報を守れた」ことは違う。秘密情報の到達率をどれだけ下げるかは、探索順序、本物と偽物の区別、他の攻撃経路、攻撃者の予算、並列性、検知後の対応時間に左右される。

## 遅滞を主要目的として評価する

攻撃者が発見を恐れ、短時間で秘密を得ようとする場合、探索の遅滞はそれ自体が攻撃の達成を難しくする。特に防御側がその間に異常を検知し、侵害された権限の停止や経路の隔離を完了できれば、デコイで得た時間が秘密への到達防止に結び付く。発見リスクを避けようと追加の行動を控える場合もあるが、攻撃者の心理は直接観測できないため、実際の行動と到達時刻で判断する。

例えば模擬攻撃で、検知から対応完了まで5分かかり、攻撃開始から検知まで2分かかると仮定する。デコイなしでは攻撃開始から6分で模擬秘密へ到達し、デコイありでは10分かかるなら、対応完了は開始から7分なので、追加の4分が防御に役立つ。この数字は説明用の仮定であり実測値ではない。通知が届かない、対応が間に合わない、他の経路が先に成功する場合は同じ遅延があっても持ち出しを防げない。

短時間で行動する動機は重要な脅威モデルだが、すべての侵入者に共通するとは限らない。長期潜伏、並列探索、情報の持ち出し後の解析も想定する。したがって遅滞の評価は、短期決着を狙う攻撃と、時間・並列性を増やす攻撃の双方で行う。遅滞が確認できても、それだけで阻止できたとは判定しない。

自動化が進むほど探索は安価になる場合がある一方、探索対象が増えれば通信・処理・モデル利用・人手確認にも費用が発生する。ただしAIの推論を使わず固定スクリプトで走査される場合もある。攻撃者は予算を増やし、罠を選別し、本物の所在を直接調べたり、別の場所から窃取したりできる。したがってAI固有の弱点の利用だけに投資するより、複数の探索方式で有効な手法を優先する。

根拠の位置付け：USENIXが紹介する対人実験はデコイによる遅延・警報の可能性を示すが、AIや本設計の性能を実証するものではない。2026年の[AgentTrap論文](https://arxiv.org/abs/2610.02869)は自律侵入テストエージェントを対象とする実験で実目標への成功率低下を報告している。ただしプレプリントであり、特定の実験環境と手法の結果であって、各案に数字を転用できない。[Rouxii論文](https://arxiv.org/abs/2609.26555)はデコイを意識するよう設定したAIペンテスターの評価で、プロンプトだけを変えた比較ではデコイ識別率が19%から97%に上がったと報告する。また、個別のOT用ハニーポットを調べた結果として、監視をすり抜けるサービス妨害や偽情報の混入も報告している。これはプレプリントであり、特定のモデル・実験環境・既存ハニーポットの結果で、本ツールや一般のAI攻撃者にそのまま当てはまるとは限らない。設計上は、デコイを知る攻撃者による識別だけでなく、デコイ基盤への能動的な探査、資源枯渇、記録の信頼性低下も評価対象に含め、デコイを本番系から隔離する。[USENIX: Imposing a Cyber Penalty](https://www.usenix.org/publications/loginonline/imposing-cyber-penalty-against-attackers-cyber-deception)

## 脅威モデル：効果が変わる状況

主シナリオでは攻撃者はデコイの有無・配置・本物の所在を事前に知らず、公開情報と探索中に見た応答を基に判断する。別途デコイを知る適応的なシナリオも試す。以下の限界は「真偽を知って回避できる」という意味ではなく、実際に観測可能な差や、事前知識がなくても生じる通常の探索行動で効果が減る場合を示す。回収後の真偽判断や見落としも別々に評価する。

| 状況 | 期待できること | 主な限界 |
|---|---|---|
| 無差別スキャン・固定スクリプト | 定番の偽URLや偽サービスへの接触を検知できる。一定の有限応答による時間消費もあり得る。 | 多くはすぐ離脱し、通知はノイズになり得る。攻撃ツールが多数同時に動けば遅延の価値は小さい。 |
| 侵入後の広範な秘密探索 | 経路上のカナリアは高い調査価値を持ち、似た候補の増加は選別に手間を生む可能性がある。 | ファイルをまとめて外部へ持ち出し後に解析されると、こちらは解析やAI費用を観測できない。読み取りは別途監査が必要。 |
| 標的型・適応的攻撃 | リアルなデコイや不確実性が時間を稼ぐ可能性がある。 | 内部情報、既知の本物、形式の差、観測点の特定、並列化で回避される可能性が高まる。デコイを積極的に探査・妨害する攻撃者も想定し、資源上限とログの保全を確認する。 |
| 正規ユーザー・スキャナ・自社AI | 正常挙動の基準と監視の正常性を確認できる。 | 自社AIも誤誘導され得る。正規クローラやバックアップで誤検知・負荷が出る。 |

## 手法別の評価

評価は「採用＝効果が期待できるため設計対象とする。対象環境での試験と安全な段階導入を行う」「不採用＝主張された仕組みが成立しない、または対象環境で容易に見破られ実用的効果がない」を意味する。採用は実証済みの性能や無条件の本番有効化を意味しない。

| 名称 | 成立する価値 | 回避・弱点 | 判断 |
|---|---|---|---|
| **カナリア・トークン（Canary Token）** | 自社管理の偽URLへのアクセス、偽資格情報の専用受信先への使用を検知。正規用途が少なければ調査優先度が高い。 | 到達しない・使用しない・通信遮断で発火しない。アクセスは犯罪やAIの証明ではない。 | **採用**：発火条件・通知・担当者が揃う場合。 |
| **コンフィグ・ファイル・トラップ（.env Canary / Semantic Maze）** | 本番とは分離した偽の.envに監視可能なURL・資格情報や有限のコメントを置き、使用の検知や探索遅滞を狙う。 | 読むだけではURL型・資格情報型は発火しない。コメントの除外・部分読み取り・偽物の識別・通信遮断で回避される。正規ツールへの影響もある。 | **採用**：発火方式を試験し、正規設定から分離して段階導入。 |
| **デコイ・データベース（Decoy Database / Honeydata）** | 複数の本物らしい偽DBで、取得後も真偽を迷わせ、誤選択や本物の見落とし、選別の遅滞を狙う。候補がすべて偽物のケースもある。 | 外部情報や特徴で識別される、全候補を保持・公開されると、本物が取得されていれば漏えい被害が生じ得る。オフライン解析は自動では検知できない。 | **採用**：合成データを専用領域に配置し、本物の取得と識別・誤選択を別々に評価する。 |
| **プリビレッジ・ハニーワード・セッション** | 偽パスワードで侵入したと考えた攻撃者が、まず一貫した偽画面から偽データを回収する場合、使用の検知・遅滞・無価値なデータの取得が期待できる。 | 偽パスワードを使用しない、MFAや画面・既知情報の差で識別する、本物を並行探索する。既存IdPが対応しない場合もある。 | **採用**：再現度を高め、正規認証・MFAを維持し、デコイ専用セッション・DBを分離。 |
| **デコイ・エンドポイント／ロー・インタラクション・デコイ** | 偽URLや限定された機能を持つサービスで探索を観測し、入力チェックや反映待ちの表示で真偽判断を遅らせる。 | 攻撃者に比較材料がなく、応答と状態が自然なら判別は難しい。既知の仕様・公開情報との矛盾や、確認しても変化しない処理状況は手掛かりになり得る。 | **採用**：入力に応じた応答と限定的な偽状態を設計し、隔離・ノイズ管理・効果を確認。 |
| **エンクリプテッド・ディープ・ネスト（Encrypted Deep Nest）** | 複数層の候補を展開・選別する作業を増やし得る。中断すると本物を見落とす可能性もある。 | 外側の特徴、既知の本物のパス、深さ制限、選択的な展開で回避。デコイを全て捨てても本物が別経路にあれば影響はない。鍵が容易に得られれば暗号自体の計算費用は小さい場合がある。 | **採用**：有限・無害なデコイを実装し、効果・負荷を測って段階導入。 |
| **インフィニット・ストリーム（Infinite Stream）** | 認証・アクセス制限のある領域で終端なくデータを返し、読み続けるクライアントの帯域や時間を消費する。早期に切れば本物も見落とす状況はあり得る。 | クライアント側のタイムアウト・部分取得・並列化で効果が変わる。終わらないことが不審に見える場合や、サーバー・中継基盤の切断もある。 | **採用**：終端のない配信を設計。同時接続・帯域の管理、停止機能、法務確認と隔離試験を行う。 |
| **アテンション・デッドロック（Attention Deadlock）** | 文書や偽指示によりエージェントの再検討・再試行を誘い、有限の遅滞を生む可能性。ゴール・ハイジャックと重なり得る。 | 自己参照だけでTransformer内部の注意機構が無限循環する根拠はない。内容を読まない、要約・無視・予算上限で終わる場合がある。 | **採用**：エージェントの行動反復として試験し、内部機構の無限停止とは区別する。 |
| **ゴール・ハイジャック（Goal Hijacking）** | 間接プロンプト注入に従うエージェントを一時的に別作業へ誘導する可能性。 | 指示とデータの分離、権限制限、予算上限、人による修正。自社や委託先の正規AIにも影響する。 | **採用**：隔離試験後、正規AIへの影響と法務を確認して限定導入。 |
| **アダプティブ・デコイ（Adaptive Decoy）** | 接触後の応答を状況に合わせ、矛盾を減らして観測時間を延ばす可能性。 | 相手の内部ガードレールや探索予算を外部から正確に知ることはできない。応答の矛盾・遅延・状態不整合で見破られる。生成AIの誤出力や運用コストも増える。 | **採用**：固定・状態管理付き応答と比較し、費用上限と隔離を設ける。 |
| **ディレクトリ・メイズ（Directory Maze）** | 有限の候補による選別作業や予算消費。本物を含む候補を深さ上限で見落とす場合がある。 | 深さ・件数制限、特徴による選別、並列化、既知経路。自社のバックアップや検索にも影響。 | **採用**：有限の構造で試験し、正規業務への影響を確認して導入。 |
| **コンテント・レングス・カモフラージュ（Content-Length Camouflage）** | 事前に見積もれない処理を相手に起こすという仮説。 | HTTP上の矛盾を検知・中断でき、プロキシや正常クライアントにも悪影響が出る。サイズを信じるしかないわけではない。 | **不採用**。正しいHTTP応答を使う。 |
| **エンコーディング・メイズ（Encoding Maze）** | 複数の有効な表現や候補の選別が追加処理を生む場合がある。 | 文字コード検出、正規化、処理上限、解析の省略。パーサーのバグが起きる保証はない。 | **採用**：通常の安全な形式を使い、効果と正規処理への影響を確認する。パーサー障害を狙わない。 |

### 選別と予算の具体例

以下は仕組みの説明用の仮定であり、測定結果ではない。10個の候補から1個の本物を探し、本物を事前に識別できず、順序も無作為で、予算上3個しか確認できない場合、本物に到達する確率は3/10。デコイがなく本物が唯一の候補なら1/1になる。この比較では候補増加が有効である。

しかし、本物が名前や外部情報で確実に識別できれば最初に選ばれ、到達率は1/1のまま。10個を並行確認できる予算があれば全て到達できる。本物が別経路でも取得できる場合も効果は減る。したがって、候補数を増やすだけでは足りず、**攻撃者の優先順位付け後も本物の順位が下がるか**を測る必要がある。本物に似せた公開データを安易に増やすと、正規利用者の混乱や漏えい面の拡大も生じるため、実データ・実資格情報は混ぜない。

データ・ディルーション（Data Dilution）は、分離デコイDBとは別の技術であり、ツールには実装しない。大量流出後の真偽選別と利用価値の低下を狙い、採用を検討する組織は合成データだけの隔離環境で効果と運用費を比較する。

URL型カナリアは持ち出し後でも実際のHTTP要求が監視先に届けば接触を把握し得る。踏み台やサンドボックスでは中継・実行環境が観測され、拡散後は第三者やスキャナーの発火が混ざる。直接・中継・通信遮断・再配布の条件を隔離環境で比較し、通知率・遅延・正規利用者の誤通知と対応前の模擬秘密到達を測る。発火だけで本人特定や攻撃の証明はできない。

デコイ・データベースでは、誤って偽DBを転売した売り手の信用低下も仮説として評価する。買い手による偽物の判定、売り手との対応付けと評価共有が必要で、信用低下やアカウント変更は未実測。許可された隔離環境の模擬取引で比較し、実市場への接触は行わない。匿名市場の評判に関する[USENIXの研究](https://www.usenix.org/conference/usenixsecurity24/presentation/cuevas)は近縁の背景であり、デコイ転売の効果を示すものではない。

真偽の確認が時間や費用を要し、それでも判定不能に終わる可能性も評価する。DB間の不一致や攻撃者自身の登録記録の不在は、収録対象・時点を確実に知る場合と知らない場合を分ける。合成データのみの隔離試験で、同じ予算のデコイなし／ありにおける判定不能率、誤判定、確認費用、目標到達率と時刻を比較する。

全件公開されても、真偽が分からなければデータの利用価値が下がる可能性は残る。外部照合は一致だけで正解とは限らず、選別精度と作業・費用を測る。判別機構の侵害、真偽を選ばない大量試行、候補ごとの真偽の公表も別条件として評価する。偽パスワードを使った場合だけ発火するハニーワードとの組み合わせは、一般の大量試行をすべて防ぐものではない。

フェイクトラップは、警告を解釈して判断するAIや人間の再確認・遅滞を狙う。ツールは異常アクセス・通報済み・認証中スピナーの静的HTMLを生成するが、実際の通報や認証は行わない。表示を無視する攻撃には別の罠を組み合わせ、効果と接触を比較する。動的な模擬応答と通知連携は未実装。

ディレクトリ・メイズに業務上のリンク集と変化するURLを加える案も検討できる。URL単位の重複排除では同様のページを再探索する可能性がある一方、正規化や本文比較で打ち切られる場合もある。AIと通常クローラーを同条件で比較する。現行GUIは有限の静的リンクを生成し、動的なパラメータ生成・HTTPリダイレクトは未実装。

## 便益・費用・導入の意思決定

- **便益**：検知機会、秘密到達の抑制、到達までの時間、インシデント調査情報。遅延が有効なのは、その間に自動または人が権限停止・遮断・秘密の失効等を完了できる場合が主である。
- **コスト**：デコイの作成・更新、クラウド費用、帯域・接続、通知対応、誤検知、正規検索やバックアップへの影響、法務・契約確認。生成AI応答は防御側にもトークン費用と不安定性を生む。
- **価値のない条件**：既に攻撃者が本物を知る、他の入口で直接取得できる、十分な並列予算がある、通知を見ない、検知前に持ち出される、デコイの特徴が明白、あるいは誤検知や稼働費が便益を上回る場合。
- **まず投資する順**：実資産の権限分離とログ → 発火条件の明確なカナリア → 限定的なロー・インタラクション・デコイ → 有限の予算消費型デコイの試験・段階導入。効果が出ない環境では調整または停止する。

## 評価設計と採用ゲート

このサンプルは正規利用者のデコイ接触でアラートが出る例を1件含みます。出力される割合や区間は説明用で、実測の誤検知率ではありません。

付属集計スクリプトの各試行レコードには、`actor`、`arm`、`budget_seconds` と任意のイベント時刻を記録する。時刻は未発生なら明示的に `null` とする。省略した時刻欄は計算上`null`として扱うが、出力の`omitted_event_fields`に群・項目ごとの省略件数を示す。省略は未発生ではなく未記録であるため、欠落がある群の結果は慎重に解釈する。正規利用者試行のsecret_timeは常に `null` とする。仕様外の項目や重複JSONキーは拒否する。これにより、イベント名の誤記を未到達・打ち切りとして黙って集計する誤りを防ぐ。

模擬秘密に届かなかった試行では、`budget_seconds` に予定上限ではなく実際の観測終了までの秒数を記録してください。予定より早く停止・中断した場合は、停止までの時間が打ち切り時刻です。予定最大時間はメタデータ雛形の `planned_time_budget_seconds` に別途記録します。

入力JSONの最上位項目は `runs` のみです。実験条件などのメタデータは別ファイルに記録してください。連携サンプルの `examples/deception-study-metadata-template.json` を使えます。入力形式の検証仕様は [`examples/deception-study-metadata-template.schema.json`](../examples/deception-study-metadata-template.schema.json)（JSON Schema Draft 2020-12）です。必須欄は空欄で用意されているため、条件を記入してから完成版を検証してください。付属の標準ライブラリCLIは `python scripts/check_study_metadata_schema.py path/to/study-metadata.json` で実行でき、2 MiBを超える入力、空または空白だけの必須説明欄を拒否します。対照・囮の差、初期情報、割付と試行順、AI・スクリプト・並列性・オフライン解析、観測ログ、停止・対応手順を記録してください。実験設計条件の記録用で、試行イベントの入力JSONとは別です。共有・配布する前に機密情報を除き、実資格情報、カナリアURL、本番情報、個人情報は記載しないでください。

付属スクリプトは、模擬秘密到達をイベント、試行期限到達を右打ち切りとしてKaplan–Meier曲線を集計し、各群の最短予算までの制限平均生存時間（秘密未到達時間）と、推定曲線が0.5に達した場合の中央値を出力する。同一の単一予算を使う対照群・囮群では制限平均の差も出し、正値はその期限内で囮群の方が秘密未到達時間が長いことを示す。予算が異なる場合は各群の最短予算までの記述値に留め、群間差は出さない。これは未到達試行を除外する到達者中央値より打ち切りを扱えるが、非対応群の記述比較であり、無作為化・条件統制なしに因果効果を証明しない。
この集計入力には、シナリオの同等性、割付方法、AIモデル、使用スクリプト、並列数、開始時に与えた情報を記録しません。これらを条件間で揃え、機密情報を含めず別の実験記録に残してください。集計結果は条件差を補正できません。

この推定は期限による打ち切りが秘密到達時間と独立していることを仮定する。攻撃者の進行状況を見て途中終了するなど、打ち切り時点が到達可能性に関係する場合は解釈が偏り得る。

遅滞は単一の「遅延秒数」にまとめない。囮接触が秘密到達より先だった試行、秘密到達が先または囮接触がなかった試行、制限時間内に秘密へ届かなかった試行を分ける。同じ時刻に記録された接触と秘密到達は順序不明として別集計し、接触が先だった試行や遅延には数えない。接触後に秘密へ届いた試行の中央値は到達できたケースだけの記述値であり、未到達試行の接触後時間は右打ち切りとして別に示す。遅延中央値には、両イベントが記録され、後のイベントが厳密に後発したペアだけを使う。同時刻・逆順のペア数は `nonpositive_latency_pairs` に別掲し、イベント順序や記録の不整合を確認できるようにする。対照群の `decoy_time` は `null` とする。いずれも対照群との比較や条件の統制なしには、囮による因果的な遅延の証明にならない。

許可を得た隔離環境に無害な模擬秘密を置き、デコイなし・カナリアのみ・有限デコイ併用を比較する。AIを用いる攻撃側は複数モデル・版と設定を記録し、AIなしのスクリプト、人間による手動操作も比較する。各試行で同じ初期情報、時間、要求数、通信量、計算・トークン予算を設定し、候補の配置順を変える。攻撃側に罠の存在を知らせる試行、部分取得・並列化・選別・予算変更・別経路の試行も用意する。追加の予算を許した比較も行い、どの程度で効果が失われるかを確認する。

主指標は「制限時間内の模擬秘密到達率の差」「到達までの時間」「検知から対応完了までの時間と、その前に秘密へ到達された割合」。副指標はデコイ到達率、通知率、誤通知、攻撃側の作業量・費用、防御側の負荷・費用、正規作業への影響。デコイなしでも取得されなかった試行を含め、全試行を分母とする。試行数、失敗・中断、信頼区間と条件を報告し、サンプル不足なら判断を保留する。

正規利用者の通常動作による基準と、デコイ設置後の誤通知・接触を比べるため、authorized の control と decoy の両方を記録する。どちらかが欠ける場合、付属スクリプトは通常時の基準または設置後の正規アクセス影響を比較できないと警告する。アラートを誤通知と判断する前に、原本ログで通常利用が原因か確認する。

付属スクリプトの `attacker_comparison` は、対照群とデコイ群の攻撃者試行が同じ単一予算の場合に限り、模擬秘密到達率の差（デコイ群−対照群）を表示する。各群ではアラート時刻が記録された試行の割合とWilson法の95%区間も表示する。群内の予算が複数あると `alert_rate_comparable_within_group` は `false` になり、観測時間の差で通知機会が変わるため単純比較できない。正規利用者群の割合は誤検知の候補指標であり、アラート原因を確認してから解釈する。同一試行で繰り返された通知数は計測しない。到達時間の中央値差は到達できた試行だけの値で、未到達試行を含まず、選択バイアスを受ける。試行は対応付けられていないため、これは記述的な比較であり、因果効果や統計的有意差を示さない。正式な採用判断には、十分な試行数と信頼区間を含む分析を別途行う。
各群の模擬秘密到達率にWilson法の95%信頼区間を、到達率差にNewcombe法の95%信頼区間を出力する。試行数が少ないほど区間は広くなり、区間が0をまたぐ場合は効果の方向も確かとはいえない。信頼区間は標本誤差を示すもので、因果関係や防止効果を証明しない。

ゲート例：担当者が事前に、許容負荷・誤通知・対応時間と、実用上意味のある到達率低下幅を定める。独立した複数シナリオでデコイありの到達率が事前設定幅以上低下し、ばらつきを考慮しても低下の根拠があり、正規利用とコストが許容範囲なら限定導入する。小標本で効果が不明、適応的攻撃で消失、または負荷・誤影響が閾値超過なら採用しない。数値閾値は資産価値と運用体制に合わせて決める。

## 法的・倫理的条件

日本を前提としても合法性は個別判断。設置権限、利用規約、個人情報、通信の秘密、業務妨害等を具体的構成に即して確認し、実環境での有効化前に専門家に相談する。ストリームは終端なしを前提に、制限領域への侵入者と正当な権限を持つ第三者のアクセスを分けて評価する。反撃、第三者への誘導、実資格情報の入力収集は行わない。実験は管理下の環境と許可済み参加者のみで行い、外部への影響、取得データ、費用上限、停止手順をあらかじめ定める。

## 試行の独立性

なお、Wilson法・Newcombe法の信頼区間は試行結果が独立した二項観測であると仮定します。同じ攻撃者、AIエージェント／セッション、運用者またはシナリオを共有する反復試行では結果が相関し、区間が過度に狭くなることがあります。その場合はクラスタを考慮した分析を別途行ってください。
