# AI時代のディセプション防御：評価と導入方針

実装と導入の対応表は [配置・検知・対応ガイド](deployment_ja.md) を参照してください。GUIは一度に一手法を選び、各手法の仕組み・脅威・限界を確認できます。設計上の採用と本番連携まで実装済みであることは区別しています。

最終調査日：2026-10-30。対象は自組織が管理し、設置を許可された環境。詳細は [設計書](agent_deception_strategy_and_design.html) を参照。

手法名を含む詳しい判断、攻撃者の行動別評価、研究と採用の条件は [多角評価](deception_evaluation.md) にまとめています。

主要な原理には先行研究や既存ツールがあります。名称の一部は本企画の呼称です。各手法と先行例の対応、同一例を確認できていない箇所は[既存手法との関係](deception_evaluation.md#既存手法との関係と新規性)を参照してください。

## 結論

ディセプションは、偽の資産へのアクセスを侵害の早期発見に役立てる補助策です。AIによる攻撃にも適用できますが、攻撃者が罠を発見する、無視する、直接本物に到達する場合は検知できません。侵入防止や被害防止の保証はなく、AIか人間かもイベントだけでは判定できません。まず認証、更新、権限分離、監視、バックアップを整えます。

**遅滞も本構想の主要な防御目的です。** 侵入者に探索・選別・確認の時間を使わせ、その間に検知、調査、権限停止や隔離を完了できれば、秘密情報への到達や持ち出しを防げる可能性があります。発見を避けたい攻撃者には、長時間の探索や追加操作が負担となり得ます。遅滞の価値は、攻撃者の到達時刻と防御側の対応完了時刻の関係で評価します。

一方、すべての攻撃者が短時間で行動するとは限りません。検知されていないと判断して長期潜伏する、並行して本物を探す、ファイルを持ち出してから解析する場合もあります。遅滞はそれ自体が侵入阻止を保証するものではなく、検知と実際の対応を組み合わせることで価値が高まります。

| 検討事項 | 判断 |
|---|---|
| 最新AIへの有効性 | カナリアへの接触は有用な手掛かり。ただしモデル、ツール、予算、対象環境で結果が変わり、網羅性は未検証。プロンプト注入も成功を保証できない。 |
| 導入容易性 | スタティック・デコイ・エンドポイントと通知は小さく始められるが、到達性、誤検知、監視、権限、運用責任者の準備が必要。数行のコピーだけで安全に導入できるとは限らない。 |
| 他の対策 | フィッシング耐性のある多要素認証、最小権限、秘密情報の短命化、出口制御、脆弱性修正、監査ログ、復旧訓練を優先する。AIエージェントには個別ID、ツール権限の絞り込み、MCP定義の変更レビュー、実行環境の隔離、重要操作の独立承認も適用する。 |
| 法律 | 日本の不正アクセス禁止法上、権限のある通常利用は抵触しないと評価し、同法・刑法上違法となる具体的な行為を手法ごとに記載します。無断ログイン、第三者管理者へのなりすまし、他者の業務妨害を行わず、個人情報は利用目的と安全管理に従って扱います。[日本法ガイド](legal_ja.md)。 |

## 机上評価と採用判断

以下は、攻撃者が自社のWebやファイルにアクセスでき、AIまたはスクリプトで探索する想定での判断です。実測値ではありません。「検知」と「相手を足止めする効果」は別に評価します。

| 手法 | 成立する効果と回避方法 | 判断 |
|---|---|---|
| スタティック・デコイ・エンドポイント | 探索がURLに到達し、サーバで記録できれば接触を検知できる。既知の本物の入口に直接進む、デコイを無視する、監視基盤を妨害することで回避可能。 | **採用**。正規アクセスが少ない探索経路への配置を検討する。 |
| カナリア・トークン | 偽URLへのアクセスや専用の偽資格情報の使用が発火すれば、利用の兆候を検知できる。ファイルを読むだけでは発火しない方式もあり、通信遮断、資格情報を試さない、偽物の識別で回避可能。 | **採用**。発火条件と監視到達性を確認する。 |
| ロー・インタラクション・デコイ | 本物に似た入力チェックや反映待ちの表示で、接触を観測し、真偽確認を遅らせ得る。比較材料がなければ攻撃者は違いを判断しにくい。 | **採用**。限定的な偽状態も保持し、通知・遅滞を評価する。 |
| アテンション・デッドロック | 文書や偽指示がAIエージェントの再検討・再試行を誘う場合、有限の遅滞が期待できる。モデル内部の注意機構が自己参照で無限停止するという根拠はない。 | **採用**。行動の反復による遅滞として試験し、モデル内部の無限停止は主張しない。 |
| ゴール・ハイジャック | 脆弱なエージェントが指示に従い寄り道する可能性はある。外部文書をデータとして扱う設計、権限制限、タイムアウトや人間による介入で回避可能。 | **採用**。まず隔離環境で正規AIへの影響を測る。自組織の防御目的に限り、第三者システムへの侵入・情報窃取・破壊を命じる指示を含めない。 |
| エンクリプテッド・ディープ・ネスト（Encrypted Deep Nest） | 展開を打ち切れば罠の処理は回避できるが、同じ基準で本物を飛ばす場合は秘密も見落とす。外側の特徴や別経路から識別できればこの効果は弱い。 | **採用**。有限の無害なデータで実装し、対象環境で効果と負荷を測る。 |
| インフィニット・ストリーム（Infinite Stream）／ディレクトリ・メイズ | 制限を超える対象を飛ばす攻撃者には見落としを生じさせ得る。ただし並行探索、部分取得、制限の調整で効果が変わる。 | **採用**。ストリームは自組織の認証付きデコイ経路に置き、正規利用者の業務経路から分離する。刑法234条の2に当たる業務妨害を起こさず、帯域・同時接続を制御する。 |
| エンコーディング・メイズ（Encoding Maze） | 複数の候補と変換層が、復元・比較・秘密の特定に追加作業を生じさせ得る。既知の形式は一括変換で復元でき、候補が同質なら選別も自動化される。 | **採用**。有限の架空候補を使い、復元時間だけでなく秘密への到達率・到達時間を比較する。暗号化や回避不能とは表現しない。 |

**採用基準：効果が期待できる手法は製品の設計対象に採用する。** 回避可能というだけでは除外しない。明らかに仕組みが成立しない主張や、対象環境で容易に識別され実用上の効果がない手法は採用しない。採用は効果の保証や無条件の本番有効化を意味しません。配置・権限・監視・負荷の条件を満たし、法的な禁止行為を避けて段階的に導入します。探索予算の消費では、秘密情報への到達率・到達時間も測る。

### 「最後まで読まないと判別できない」場合

ご指摘のトレードオフは成立します。攻撃者にとって本物とデコイが途中まで区別できず、秘密が後半にある可能性があり、探索予算が限られるなら、上限を厳しくするとデコイを避ける一方で本物も見落とし得ます。上限を緩めると、デコイに時間や処理を使う可能性が高まります。これはAIに限らず探索全般の問題です。

ただし、最後まで判別できないことは設計だけで保証できません。攻撃者がファイルのサイズ・形式・名前などで優先順位を付ける、部分取得や並列探索を行う、既に本物の場所を知る、上限を変更する場合は効果が下がります。攻撃者が罠を飛ばしても本物に別経路から到達すれば、防御目標は達成されません。逆にデコイを処理しただけで本物への到達を阻止できたとも言えません。

試験では、実際の秘密の代わりに無害な模擬秘密を置き、デコイなし・ありで、同じ時間・通信量・試行予算の下での**模擬秘密への到達率と到達時間**を測ります。部分取得、並行探索、上限変更、適応的な攻撃も比較し、正規ユーザーへの影響と防御側の負荷を測ります。試験結果に応じて配置や上限を調整し、効果が得られない環境では無効化します。

エンクリプテッド・ディープ・ネストは、本物と偽物を見分けにくく、限られた予算内で候補を調べる状況では有効性が期待できるため採用します。デコイを見つけた後、別途回収した本物の暗号化ファイルまで偽物ではないかと疑わせ、解凍・確認を続けるか、価値が不明なまま捨てるかの判断を難しくすることも狙います。疑いが広がるかは未検証です。復号処理自体の費用と、候補を探して内容を確認する費用は別です。本物を識別できる手掛かりや別経路、正規運用への影響を確認し、有限の無害なデコイから導入します。

公開研究ではAIのプロンプト注入に対する耐性が改善する一方、完全ではありません。ただし、その結果はこの製品の成功率には転用できません（[Anthropicの評価](https://www.anthropic.com/research/prompt-injection-defenses)）。また、AIがコード作成に使われても侵入後の操作はスクリプトや人間が行う場合があり、AI特有の罠だけに依存すべきではありません（[観測事例](https://www.anthropic.com/research/attack-navigator)）。

攻撃者側にもデコイを見分けるAIや手順がある前提で評価します。2026年の[Rouxiiプレプリント](https://arxiv.org/abs/2609.26555)は、特定の評価でデコイ識別率が19%から97%に上がった比較と、個別のOT用ハニーポットへの妨害を報告しています。これは本ツールの有効率や一般的な攻撃成功率を示すものではありませんが、デコイの本番系からの隔離、資源上限、ログ保全が必要な理由になります。詳細は[多角評価](deception_evaluation.md)を参照してください。

## 対策の優先順位

1. **MVP：スタティック・デコイ・エンドポイントとカナリアファイル。** 専用の偽URLや無害なファイルを設置し、実際のアクセスを記録・通知する。ファイルを読むだけでは通知されない方式がある。カナリア資格情報には本番資産への権限を与えない。
2. **隔離されたロー・インタラクション・デコイ。** 入力に応じた応答や限定的な偽状態を返し、本番の権限・データを持たない。機器やサービスの脆弱性を模倣して実行させない。
3. **探索予算を消費させるデコイ。** エンクリプテッド・ディープ・ネスト、インフィニット・ストリーム、ディレクトリ・メイズ、エンコーディング・メイズを採用候補として扱い、隔離試験後に対象環境へ段階導入する。ストリームは正規利用から分離した認証付き経路に配信し、帯域・同時接続と停止手段を設ける。メイズ類は有限の候補群を使い、復号・一括取得で容易に処理される可能性を評価する。ゴール・ハイジャックは自組織防御の有限な案内に限定し、第三者システムへの侵入・窃取・破壊の指示を含めない。

### .env などのテキストファイルを使う罠

**採用する手法です。** 本番アプリが読み込む設定とは分離した偽の `.env` や設定ファイルに、監視可能な専用URLやカナリア資格情報を配置します。ファイルの読み取り自体は通知されず、URLへのアクセスや資格情報の使用など、各方式の発火条件を満たしたときに検知します。読み取りを検知するには別途ファイル監査が必要です。ランダムな偽キーや架空ドメインを置くだけでは通知されません。

持ち出し後に外部接続可能な環境からURLが実際に要求されれば、接触の手掛かりを得られる可能性があります。踏み台やサンドボックスからの要求では、その環境のIP等が記録されても攻撃者本人とは断定できません。ファイルが拡散された場合は第三者やスキャナーの発火も混ざるため、配置台帳や他のログと照合します。通信遮断、URLの未使用や通知遅延も考慮します。

攻撃者のAIがコメントを読む場合は、有限のダミー文書や偽指示で探索に時間を使わせる可能性もあります。ただしコメントの除外、部分読み取り、要約、指示の無視で回避され得ます。正規の開発者やAIも対象ファイルを読めるため、隔離試験と誤影響の確認が必要です。具体的な発火条件、設置例、運用手順は[設計書](agent_deception_strategy_and_design.html#env-decoy)に記載しています。

### デコイ・データベース（Decoy Database / Honeydata）

選別の遅延に加え、攻撃者が偽DBを本物として転売し、買い手が偽物と判断して評価を共有すれば、売り手の信用や今後の取引に影響する可能性も狙います。信用の低下やアカウント変更が起きるかは未検証で、取引の仕組みや買い手の検証方法に左右されます。

真偽確認に労力を費やしても確かな結論に至らないことも狙います。DB間のユーザーの不一致は収録範囲や更新時点の違いでも起こるため、単独では偽物の証拠とは限りません。攻撃者が登録したアカウントの不在も、対象と収録時点を確実に知っているかで判断の強さが変わります。現行生成器は実ユーザーを取り込まず、確認の難しさは未測定です。

**採用する手法です。** 本物に似たテーブル構成と架空のレコードを持つ偽DBを複数配置し、窃取後もどれが本物か判断する手間を増やします。本物も取得された場合でも、偽物を本物と勘違いし、本物を見落とす可能性があります。ただし外部情報等で識別されたり、全候補を公開・売却されたりする場合は、本物の漏えい被害が生じ得ます。ダウンロードやDBアクセスには対応する監視が必要で、持ち出し後のオフライン解析は自動通知されません。

ツールには顧客、カード台帳、企業、パスワード保管庫、注文、請求、従業員、取引先、問い合わせ、資産、クラウド資産の11個の編集可能な雛形があります。カード番号・CVVや利用可能なパスワード・認証ハッシュは生成しません。DB監視、実データの取り込み、複数テーブル関係は未実装です。

実レコードは使わず、本番アプリ・バックアップ・復旧データへの混入を防ぎます。実スキーマも情報として扱い、再現してよい範囲を判断します。詳細は[設計書](agent_deception_strategy_and_design.html#decoy-database)に記載しています。

[データ・ディルーション（Data Dilution）](agent_deception_strategy_and_design.html#mixed-decoy-records)は、本番DBに合成ダミーを混ぜて流出後の選別とデータ価値の低下を狙う、上記の分離デコイとは別の技術です。ツール内では技術紹介のみを行い、実装しません。効果と運用費は未検証です。

### フェイクトラップ

警告や認証中のスピナーを静的HTMLとして生成し、表示を解釈するAIや人間の再判断による遅滞を狙います。実際の検知・通報・認証は行わず、アクセス記録と通知は配信側で別途必要です。表示を無視する攻撃への効果は限定的で、遅滞は未測定です。

### プリビレッジ・ハニーワード・セッション

偽の認証情報を使った相手を隔離デコイへ誘導する案は、この手法に含めます。ここでは特権ユーザーの偽パスワードを扱い、別の偽アカウント方式を実装済みとは扱いません。

**採用する手法です。** 対象の特権ユーザーに正規パスワードとは別の偽パスワードを複数登録し、その一致時には偽データを表示する隔離環境に誘導します。設定変更は偽環境だけに反映し、操作の観測と遅滞を狙います。一般ユーザーや偽パスワードにも一致しない入力は通常どおり認証失敗とします。

偽パスワードの一致は本番認証成功と扱わず、デコイ用セッション・DBを分離します。正規パスワードでは既存のMFAと試行制限を維持します。偽パスワードを外部ファイルに配置する必要はなく、総当たりによる偶然の一致と、データ・ディルーションの偽認証情報を試す場合を評価します。推測困難な値は試行回数によって一致しにくく、推測されやすい値は正規利用者の誤入力も増え得ます。既存IdPが対応しない場合は導入できず、偽一致がなければ誘導されません。詳細は[設計書](agent_deception_strategy_and_design.html#dummy-user)を参照してください。

ログインに成功したと考えた攻撃者が、まずデータを回収するケースを主シナリオにします。偽画面・一覧・ダウンロード・設定変更後の表示を一貫させれば、誤認を維持し、偽データへのアクセスを検知して対応時間を得られる可能性があります。本物のMFAを緩めず、偽環境で実際のMFA情報を求めないため、MFAの見え方の差は対象環境ごとに検証します。

従来案にあった「注意機構の無限停止」「回避不能」「暗号化で事前検査を完全無効化」「数日間の拘束」は実証されていません。アテンション・デッドロックはエージェントの行動反復による遅滞として採用します。ストリームは終端を設けず、同時接続と帯域の管理および停止手順を設けます。虚偽のContent-Lengthは容易に検出され得るため不採用とし、反撃や第三者への誘導は行いません。

## 導入と検証

まず隔離環境で、通常の利用者・クローラ・スキャナが触れない場所にカナリアを配置します。通知先、担当者、保持期間、停止手順を決め、手動のテストアクセスから通知と調査まで確認します。本番では限定範囲で開始し、誤検知、検知漏れ、通知遅延、負荷、運用コストを測ります。デコイ単独で自動遮断せず、他の証拠と合わせて人が判断します。

個人開発者・中小企業向けに、Pythonで起動するローカルWeb GUIを提供しています。GUIから一手法を選び、対応形式やシナリオを設定して配置用ファイルと管理者専用台帳を生成できます。生成器はファイルを自動配置せず、URLへ接続もしません。公開先への配置、監視URLの発行、アクセスログ・通知の設定は利用者が行います。カナリア通知には常時稼働する受信サービスまたは既存サービスが別途必要で、静的なWebファイルだけでは偽ログインや状態保持を実現できません。詳細な必要環境と手順は[日本語README](../README_ja.md)と[配置・検知・対応ガイド](deployment_ja.md)を参照してください。

AIの効果は、許可された複数のモデル・バージョンと、固定スクリプトおよび人手の比較群で検証します。モデル名、設定、予算、試行数、探索経路、デコイ到達率、通知率、誤検知率、時間と費用を記録し、未到達も失敗として数えます。少数の成功例を一般化せず、再現可能な評価まで効果は仮説とします。

## 法務・プライバシー

自社所有であっても、共有環境や委託先では管理権限・契約・利用規約を確認します。第三者へのアクセス、反撃、認証情報の収集、第三者ドメインへの誘導、無制限の負荷は避けます。IPアドレスやアクセス履歴は状況により個人情報等に該当し得ます。利用目的、取得範囲、保持・削除、アクセス制御、委託・国外移転、通信の秘密の適用を確認します。ログ本文や秘密情報は原則保存せず、証拠保全が必要なときは別途手順を定めます。

参考： [OWASP Prompt Injection](https://genai.owasp.org/llmrisk/llm01-prompt-injection/)、[Anthropicの評価](https://www.anthropic.com/research/prompt-injection-defenses)、[警察庁 不正アクセス対策](https://www.npa.go.jp/bureau/cyber/countermeasures/unauthorized-access.html)、[個人情報保護委員会 ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)。

本ツールには[1分単位の高速サインイン失敗KQL例](../examples/entra-signin-velocity.kql)と、Entra監査・Graph操作を確認する解析例があります。これらは個別にSIEM等へ設定する調査シグナルで、ARTEX固有検知、侵害の断定、データ持ち出しの検出、自動遮断を行うものではありません。短時間で権限取得・永続化まで進む事例を前提に、認証・アプリ資格情報・権限変更の監視と担当者への通知をデコイ運用と並行して準備してください。
