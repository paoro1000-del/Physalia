# 日本法上の見解：各手法と不正アクセス禁止法

日米の説明は一般的な一見解であり、個別の適法性を保証しません。実際の導入前に、対象となる地域と具体的な構成に詳しい法律の専門家へ確認してください。

## 米国法上の見解

確認日：2026年10月31日。自組織または明示的に権限を与えられた環境でのデコイの生成・配置自体は、通常、それだけで第三者システムへの無断アクセスには当たりません。ただし構成や実際の操作により評価は変わり、他の法令や契約の適用を否定するものではありません。

連邦の[Computer Fraud and Abuse Act（18 U.S.C. § 1030）](https://uscode.house.gov/us/usc/119-118/t18/s1030/)は、一定の要件の下で無権限アクセスや権限を超えるアクセス等を扱います。攻撃元に見える第三者設備への侵入や他人の認証情報を使った無断ログインは、防御目的でも問題となり得ます。司法省の[起訴方針](https://www.justice.gov/jm/jm-9-48000-computer-fraud)は省内の方針であり、条文の全範囲や民事責任を尽くすものではありません。

アクセスログと、通信内容のリアルタイム取得・保存・開示は区別します。連邦の[18 U.S.C. § 2511](https://uscode.house.gov/us/usc/119-120/t18/s2511/)は一定の通信傍受等を規制し、例外にはそれぞれ要件があります。自社設備だから通信内容を自由に傍受できる、あるいは同意が一つあれば常に適法だとはいえません。州の通信・プライバシー法、保存された通信に関する規則、業界固有の法令、契約や通知義務も構成により関係します。収集する項目、関係者の所在地、通知・同意、保存期間、アクセス権限と外部監視事業者への提供を確認します。

偽DBやデータ・ディルーションでは第三者の実情報の混入や誤送信、フェイクトラップでは実在機関へのなりすましや正規利用者の混乱、無限配信では第三者の資源への損害、ハニーワードでは認証情報や通信内容の収集をそれぞれ検討します。IPやUser-Agentなども取扱い次第でプライバシー上の問題になります。必要な範囲の記録、保管・削除・アクセス制限については[FTCの個人情報保護ガイド](https://www.ftc.gov/business-guidance/resources/protecting-personal-information-guide-business)も参照してください。

確認日：2026年10月30日。対象は、このツールが提供する生成物・サンプルを、自組織または設置の権限を与えられた環境で使う場合です。表の「通常は該当しない」は、不正アクセス禁止法に照らした一般的な見解であり、全ての法令について無条件の適法性を保証するものではありません。

同法は、ネットワーク経由で他人の識別符号を無断で使う、またはアクセス制御の制限を免れる情報・指令を入力して制限された利用が可能な状態にする行為などを禁止します（第2条第4項・第3条）。取得・保管・提供や、識別符号の入力を不正に要求する行為にも、それぞれ別の要件があります（第4〜7条）。第7条は、識別符号の入力を求める情報を公衆閲覧可能にする行為と、その情報を電子メールで利用権者に送信する行為を対象にしています。条文上の行為要件は「アクセス管理者になりすまし、その他当該アクセス管理者であると誤認させて」と規定されています。個別事案への当てはめは表示内容、配信先、関係者、承諾の範囲などによります。同条ただし書は、当該アクセス管理者の承諾を得た行為を対象外とします。この例外は同条の適用に限られ、他法令の責任まで免除するものではありません。立法時の国会審議では、サイト管理者等が承諾した啓発・訓練用フィッシングサイトが例示されています。[e-Gov：不正アクセス禁止法（2026年10月30日時点）](https://laws.e-gov.go.jp/law/411AC0000000128?occasion_date=20261030)／[警察庁：法律の解説](https://www.npa.go.jp/bureau/cyber/pdf/1_kaisetsu.pdf)／[衆議院：2012年3月16日内閣委員会議事録](https://www.shugiin.go.jp/internet/itdb_kaigirokua.nsf/html/kaigirokua/000218020120316004.htm)

警察庁の現行の違法情報案内も、「識別符号の入力を不正に要求する行為」を不正アクセス禁止法第7条第1号として掲載しています。[警察庁：インターネット上の違法情報・有害情報対策](https://www.npa.go.jp/bureau/cyber/countermeasures/illegal-info.html)

## GUIの手法

| 手法 | 通常利用の評価 | 同法に抵触し得る具体的な行為・別の考慮事項 |
| --- | --- | --- |
| カナリアファイル | 正当に発行された監視URLを、自組織の偽ファイルに配置すること自体は、同法上の不正アクセスに通常は該当しない。 | 他人の実際の識別符号を業務その他正当な理由なく第三者に提供することは第5条、これを使って無断ログインすることは第2条・第3条に抵触し得る。利用を許可されたカナリアサービスのURLを設定すること自体は、この例とは異なる。 |
| デコイ・データベース | 架空レコードを生成し、権限のある領域に配置すること自体は通常は該当しない。 | 生成のために第三者のID・パスワードを無断使用して制御を突破すれば第2条・第3条に該当し得る。実際の個人情報を取り込む場合は、別途個人情報保護法の取扱いが問題となる。 |
| スタティック・デコイ・ポータル | 管理権限のある領域で静的な偽画面を配信すること自体は通常は該当しない。現在の生成物はログイン画面を含まない。 | アクセス管理者になりすまし、または管理者であると誤認させ、利用権者に識別符号の入力を求める情報を公衆閲覧可能にする、または電子メールで利用権者へ送信する行為は第7条に抵触し得る。実際に入力・取得されたことは必須ではない。同条ただし書は、当該アクセス管理者の承諾を得た行為を対象外とする。具体的な当てはめは表示内容、配信先、関係者及び承諾の範囲による。 |
| ランサムウェア・デコイフラッド | 自組織が管理する環境に架空ファイルと補充スクリプトを配置する通常利用は、それ自体が同法上の不正アクセスとは限らない。 | 他者の端末・共有領域に無断で配置・監視することや、共有資源を消費することは別途検討が必要。プロセス停止や復元は行わない。 |
| パス・メイズ、スパース・デコイ | 管理する環境に架空ファイルを配置すること自体は通常、第三者システムへの不正アクセスには当たらない。 | 他者の領域への無断配置や共有ストレージ・バックアップ容量の消費は、権限や契約に応じて検討する。 |
| エンクリプテッド・ディープ・ネスト | 権限のある環境で暗号化ZIPと架空文書を生成・配置すること自体は通常は該当しない。 | 他人の認証情報で保護されたサーバーに無断ログインすれば第2条・第3条に該当し得る。ZIPをオフラインで復号することだけを、同法上の不正アクセスとは断定しない。 |
| インフィニット・ストリーム | 権限のある自組織の配信サーバーで終端のない応答を返すこと自体は、同法上の不正アクセスに通常は該当しない。 | そのために他人のアクセス制御を無断突破すれば第2条・第3条に該当し得る。無限配信で正当な第三者に損害が生じる場合は、同法とは別に業務妨害や損害賠償が問題になり得る。具体的な故意・過失、予見可能性、因果関係などによる。公開場所に置いたことだけで直ちに違法とも、認証付きなら免責とも断定しない。 |
| ディレクトリ・メイズ | 権限のある配信先に有限のディレクトリやリンクを設置すること自体は通常は該当しない。 | 第三者の管理するサーバーに認証を無断突破して配置する場合は、第2条・第3条に該当し得る。 |
| エンコーディング・メイズ | 架空データのエンコード・復元・配置自体は通常は該当しない。 | 回収した他人の識別符号を使って制御されたサービスへ無断ログインすれば第2条・第3条に該当し得る。オフラインの変換処理自体を不正アクセスと断定しない。 |
| 認証・クラウド操作ログの分析 | 閲覧権限のあるログをローカルで分析すること自体は通常は該当しない。 | 調査を理由に他人の認証情報でアクセス制御を無断解除すれば第2条・第3条に該当し得る。ログ内の個人情報等の取扱いは別途確認する。 |

## サンプル・設計にある手法

| 手法 | 通常利用の評価 | 同法に抵触し得る具体的な行為・別の考慮事項 |
| --- | --- | --- |
| ロー・インタラクション／アダプティブ・デコイ | 自組織の権限ある環境で偽状態を返すこと自体は通常は該当しない。提供するのは状態保持の部品例で、認証画面や通知の完成品ではない。 | 別のアクセス管理者になりすます、または管理者であると誤認させて、そのサービスの識別符号入力を求める情報を公衆閲覧可能にする、または電子メールで利用権者へ送信する行為は第7条に抵触し得る。具体的な表示・配信先・関係者・承諾の範囲を確認する。 |
| プリビレッジ・ハニーワード・セッション | 当該認証のアクセス管理者が、偽一致時に自組織の隔離環境へ分岐する設計は、通常は同法上の不正アクセスに該当しないと評価する。これは条文に基づく見解であり、この構成の判例を確認したものではない。 | 第三者のサービスの管理者になりすます、またはその管理者であると誤認させて、そのサービスの利用者に識別符号を入力させる情報を公衆閲覧可能にする、または電子メールで利用権者へ送信すると、第7条に抵触し得る。本番MFAを維持し、偽一致で本番権限を発行しない。 |
| アテンション・デッドロック／ゴール・ハイジャック | 文書の作成・自組織への配置だけを、直ちに不正アクセス禁止法違反とは評価しない。 | AIに第三者のアクセス制御の突破や他人の識別符号の無断使用を実行させれば、具体的な行為に応じ第2条・第3条が問題となる。自然言語の指示が刑法168条の2の不正な指令等に当たるかは具体的な内容・目的等による。すべての指示が直ちに該当するとはいえない。 |


## 2026年の個人情報保護法改正

個人情報保護法等の一部改正法は2026年7月17日に公布されていますが、改正内容の多くは確認日時点で未施行です。法律附則では、原則として公布後2年以内に政令で定める日から施行し、一部の列挙された規定は公布から6か月後に施行すると定めています。個人情報保護委員会は政令・規則・ガイドラインを整備中です。このガイドの個人情報保護法に関する記述は、確認日時点の施行法令に基づきます。施行日と運用ルールの確定後に再確認してください。[個人情報保護委員会：2026年改正法の状況](https://www.ppc.go.jp/personalinfo/legal/r8kaiseihogohou/) / [改正法附則・施行期日](https://www.ppc.go.jp/files/pdf/260717_houritsu.pdf)

## 権限、反撃、第三者への拡散

防御のためでも、他人のシステムを無断で操作できる権限は生じません。攻撃者に見えるIPが踏み台や第三者サービスであることもあります。検知後は自組織内の遮断、資格情報の失効、証拠保全、事業者・警察への連絡など、権限のある対応を行います。

カナリアURLの発火先にも、アクセス元IPアドレス・時刻・User-Agent等が送られ、発行元やホスティング事業者のログに記録される場合があります。収集項目・保存期間・保管地域を確認し、URLに顧客ID等を含めず、ログへのアクセスを制限してください。送信元IPだけでは攻撃者本人と断定できません。アクセス情報が個人情報または個人関連情報に当たるかは他情報との照合可能性や利用状況によります。個人情報保護委員会は個人を識別できない端末識別子等が個人関連情報に該当し得ると説明しています（[通則ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)）。

他人の識別符号の取得は、不正アクセス行為に使う目的がある場合に第4条、**不正に取得された**識別符号を不正アクセス行為に使う目的で保管する場合に第6条が問題になります。偶然見つけた、又は防御目的で正当な権限に基づき取り扱う場合まで一律に違法とするものではありません。第5条の提供には「業務その他正当な理由」の例外があります。[警察庁解説：第4〜7条](https://www.npa.go.jp/bureau/cyber/pdf/1_kaisetsu.pdf)

ファイルやURLを取得した第三者について、ダウンロードだけをもって不正アクセスと断定することはできません。識別符号の利用、アクセス制御の有無、利用権限と具体的な操作を確認します。拡散されたデータやURLによる損害も、直ちに設置者の責任が確定するわけではなく、予見可能性・因果関係などによります。

特に、配布先のAIに第三者の秘密情報・個人データを外部送信させる目的で、ファイルへ誘導指示を埋め込む設計は採用しません。受領者がそのファイルをAIへ渡すことを予見できたか、情報流出を意図・容認したか、指示と損害の因果関係などによっては、民法709条の不法行為責任や契約上の責任、個人情報保護法上の問題が別に生じ得ます。ファイルを置いたことだけで責任が自動的に決まるわけでも、第三者がAIへ入力したことだけで設置者が常に免責されるわけでもありません。生成AIへ個人データを入力する利用者側にも、利用目的や提供先の取扱いを確認する必要があります。[民法709条](https://laws.e-gov.go.jp/law/129AC0000000089?occasion_date=20261030)／[個人情報保護委員会：生成AIサービスの利用に関する注意喚起](https://www.ppc.go.jp/news/careful_information/230602_AI_utilize_alert/) / [PPC FAQ: クラウドAIへの個人データ入力](https://www.ppc.go.jp/all_fad_index/fad2-3-3-q1/)

アクセスログやメールアドレスは、他の情報と容易に照合して個人を識別できる場合、個人情報に該当し得ます。保存期間、アクセス権限、利用目的を適切に設定します。[個人情報保護委員会の説明](https://www.ppc.go.jp/all_faq_index/faq2-q2-2/) と[通則ガイドライン（2026年6月改正）](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)を参照してください。刑法の不正指令電磁的記録等の要件は[刑法168条の2（2026年10月30日時点）](https://laws.e-gov.go.jp/law/140AC0000000045?occasion_date=20261030)を参照してください。
