# まずはサンプルを作る

## 1. アプリを起動する

起動スクリプトはPython 3.14、3.13、3.12、3.11の順に探します。3.15以降は現在未対応です。WindowsでPythonが未導入なら、[Python公式ページ](https://www.python.org/downloads/)からPython Install Managerを入れ、コマンドプロンプトを開き直して `pymanager install 3.14` を実行して対応版を入れてください。ManagerとPython実行環境は別です。起動スクリプトも、対応したPython実行環境が導入済みであることを確認してから起動します。macOSでは公式ページからPython 3.14.xのインストーラーを選んでください。Linuxでは、多くのディストリビューションが対応版Pythonを提供しています。見つからない場合は、[Python公式のLinux導入案内](https://docs.python.org/3.14/using/unix.html#on-linux)を参照してください。

- Windows: `start_windows.bat` をダブルクリックします。
- macOS / Linux: ターミナルで `sh start_unix.sh` を実行します。

画面はこのPC内だけで動作します。作成したファイルはブラウザーのダウンロード先に保存され、Webサイトへ自動公開されません。

起動スクリプトが専用の仮想環境を作成します。初回は固定バージョンの依存パッケージを準備するため、インターネット接続が必要な場合があります。起動後にブラウザーが開きます。開かない場合は、起動画面に表示されたURL（通常は `http://127.0.0.1:8765/`）をブラウザーに入力してください。サーバーを止めるときは起動した画面で `Ctrl+C` を押します。標準ポートが使用中の場合は、`sh start_unix.sh --port 8766`または`start_windows.bat --port 8766`のように別のポートを指定してください。

パッケージのインストール中に停止した場合は、インターネットに接続していることを確認し、起動スクリプトを再実行してください。スクリプトは確認済みの固定バージョンのみをハッシュ検証付きでインストールします。エラーを避けるためにバージョンやハッシュの制限を外さないでください。解決しない場合は、起動画面のエラー全体を保存し、管理者または開発者へ相談してください。

## 2. 手法を理解してからサンプルを作る

初めて使うときも、先に手法を選び、その仕組みと注意点を確認してから生成します。

1. 左側の「対策サンプル生成」を開きます。
2. 手法カードを一つ選びます。
3. 「この手法を知る」を読み、仕組み、想定する攻撃、効果が弱まる条件、検知・対応の準備、法的な注意を確認します。
4. 設定を確認・調整し、画面下部の「ファイルを生成」を押します。
5. ダウンロードしたファイルをプレビューし、内容と配置先を確認します。

形式や件数などは、選択した手法の設定欄で指定します。カナリアURLは監視サービスが発行したURLだけを入力してください。生成器はURLへ接続しません。ファイルを開いただけでは通常通知されず、配置後にURLへアクセスがあったとき監視サービスが記録します。運用者自身のクリックやクローラーも記録の原因になる場合があります。

### サンプルの種類

- **カナリアファイル:** HTML、PDF、TXT、JSON、CSV、Excel、PowerPoint、SQLite、`.env`などから形式を選び、用途と架空データ件数を設定します。`.env`は件数を使いません。
- **静的デコイポータル:** 用途とタイトルを設定します。配置用ZIPにはHTMLと架空文書が含まれ、ログイン機能はありません。
- **デコイ・データベース:** 顧客、売上、ユーザー管理などの雛形を選び、件数と項目を確認します。実カード番号やCVVは含まず、パスワードやAPIキーの見本は認証に使えません。既存DBには接続しません。
- **暗号化ディープ・ネスト、ディレクトリ・メイズ、エンコーディング・メイズ:** 説明と見積もりを読み、サイズ・階層・件数を調整します。運用者専用ファイルは配置物と分けて保管してください。
- **説明のみの手法:** 「説明のみ」とある手法は考え方の紹介で、サンプル生成や本番環境の変更は行いません。

生成物は架空データで、ブラウザーから保存されます。アプリがWebサイトへ公開・配置することはありません。本番設定に投入せず、管理下の隔離環境で確認してください。

### ZIPとデータベースの確認

ZIPを確認するには展開して`index.html`を開きます。Webサイトとして使う場合は、自分が管理するテスト環境へ手動で配置します。DBは信頼できるSQLiteビューアで確認してください。暗号化ディープ・ネストの配置用ZIPと運用者専用JSONは分けて保存し、後者を公開ディレクトリへ置かないでください。

初期状態の`.env.development`は、有効行とコメント行の両方に予約済み`example.invalid`の見本値を使います。詳細設定にURLやメモを入力した場合は、生成前に確認してください。実アプリ設定には読み込ませず、隔離環境だけで使ってください。

## 3. 保存したファイルを確認する

ファイル名は選んだ用途に合わせて自動で設定されます。詳細設定にファイル名欄がある方式では、必要に応じて変更できます。空欄のままでも作成できます。

ファイルはブラウザーのダウンロード先に保存されます。自動保存されない場合は、生成結果に表示されるファイル名リンクを押してください。HTMLは「新しいタブでHTMLをプレビュー」、PDFは「新しいタブでPDFをプレビュー」から内容を確認できます。単体HTMLは見た目のプレビュー用です。ポータルの配置用ZIPには、ファイル一覧から文書を開ける`index.html`と`documents`フォルダーが入っています。ZIPを展開し、この2つを同じWebサイトのフォルダーに配置すると、監視URLを指定しない場合は一覧から6件の架空文書を開けます。監視URLを指定した場合は1件のリンクが監視先を向き、残り5件をページから開けます。HTMLプレビューを開くだけではカナリアURLへ接続しません。ページ内のカナリアリンクをクリックすると、監視サービスに記録・通知される場合があります。Webサイトへ自動配置はされません。DB・Excel・PowerPointの生成後プレビューは、先頭10件までです。全件を調べる場合は、ダウンロードしたSQLiteファイルを手元で信頼しているSQLite対応ビューアで開いてください。`.env`のZIPを使う場合は、WindowsではZIPを右クリックして「すべて展開」、macOSではZIPをダブルクリックします。展開先にできる`.env.development`を確認してください。

プロジェクト内に一時保管する場合は、リポジトリ直下の`generated/`に置くとGit管理から除外されます。除外設定だけに頼らず、公開前に`git status --short`で登録対象を確認してください。

### 暗号化ディープ・ネストのZIPを開く場合

ブラウザーのダウンロード欄から、配置用の`*_deployment.zip`と管理用の`*.operator.json`を両方保存します。配置用ZIPを展開して暗号化ZIPを取り出し、管理用JSONでそのZIPに対応するパスワードを確認してください。AES暗号化ZIPに対応した展開ソフトで開き、内側にZIPがあれば同じ手順を繰り返します。管理用JSONには全階層のパスワードと配置情報が含まれます。公開・配置せず、アクセス制限された別の場所に保管してください。管理用JSONを失うと、パスワードが分からず、暗号化ZIPを開けなくなる場合があります。

## 4. 配置する場合

最初は本番環境ではなく、自分が管理する試験用サイトまたは別サーバーで試してください。これは、本番サイト・本番データベース・実際のユーザーアカウントから切り離した場所です。Webサイトで公開するファイルだけを配置し、本番の認証情報やデータは置かないでください。`.operator.json`や`.inventory.json`などの管理者専用ファイルは、Webサイトから誰でも取得できるフォルダーの外に保管してください。生成物には入力したカナリアURLが含まれる場合があるため、公開GitHubリポジトリへ登録しないでください。ログイン制限、HTTPS、アクセス記録、通知先は配置先で設定します。
