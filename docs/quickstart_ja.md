# はじめに

アプリは起動済みです。左側の「対策紹介とサンプル生成」から始めましょう。

## 1. 手法を理解してからサンプルを作る

初めて使うときも、先に手法を選び、その仕組みと注意点を確認してから生成します。

1. 左側の「対策紹介とサンプル生成」を開きます。
2. 心配なことを選んで候補を絞り、対策のカードを一つ選びます。
3. 「この手法を知る」を読み、仕組み、想定する攻撃、効果が弱まる条件、検知・対応の準備、法的な注意を確認します。
4. 設定を確認・調整し、画面下部の「ファイルを生成」を押します。
5. ダウンロードしたファイルをプレビューし、内容と配置先を確認します。

形式などは、選択した手法の設定欄で指定します。一部の手法では件数も指定できます。カナリアファイルにはこのPC用のURLが最初から設定されます。外部の監視サービスを使う場合は、そのサービスが発行したURLに変更できます。生成器はURLへ接続しません。ファイルを開いただけでは通常通知されず、URLへアクセスがあったとき監視サービスまたはローカル接触ログに記録されます。運用者自身のクリックやクローラーも記録の原因になる場合があります。

同じPCでの動作確認には、最初から設定されたURLを使えます。Physaliaが稼働中にそのURLへアクセスすると、左メニューの「カナリア接触ログ」で時刻・HTTPメソッド・識別子と、送信された接続元IP、User-Agent、言語、ブラウザーのクライアントヒントなどを確認できます。送信されなかった項目は表示されず、値は偽装される場合があります。このURLは`127.0.0.1`を使うため同じPC専用で、接続元IPも通常は`127.0.0.1`です。別PCに配置したファイルからはPhysaliaに届きません。起動中のサンプルでは同じURLを使うため、ログからファイルを区別できません。最大500件のログはメモリに保存され、終了すると消えます。再起動するとURLが変わり、それ以前のURLは使えません。別PCで監視する場合は、その環境から到達できる監視先を用意してください。

カナリアページをブラウザーで開き、JavaScriptが動作する場合は、画面・表示領域のサイズ、タイムゾーン、言語、論理CPU数、メモリー容量の目安、タッチ・自動操作フラグ、ブラウザーが公開するプラグインやGPU情報、クライアントヒントなども取得し、同じローカルサーバーに送ります。ブラウザーの種類や設定、ブロックにより項目が得られないことがあります。JavaScriptを実行しないスクリプト等ではHTTP接触だけが記録されます。ブラウザーとOSの表示はUser-Agentからの推定で、自動操作フラグやGPU情報だけでサンドボックスや攻撃者を特定できません。

カナリアページは位置情報の利用許可も求めます。許可された場合、ブラウザーが返した緯度・経度、精度、取得時刻と、得られる場合は高度・方位・速度を同じローカルサーバーに記録します。既に許可済みの場合は新たな確認が出ないことがあります。拒否、非対応、タイムアウトやJavaScript未実行の場合もHTTP接触は記録されます。ブラウザーによってはページの「位置情報を送信」を押す必要があります。ブラウザーやOSの位置情報サービスがネットワークを使う場合があり、返された値も概算や偽装の可能性があるため、攻撃者本人の位置とは断定できません。

各ヘッダーと文字列は最大512文字を記録します。Authorizationヘッダー、Cookie、カナリアへの任意のリクエスト本文、参照元URL、クエリ文字列はログに記録しません。追加情報の受信には、項目を限定したJSONを使います。アクセス情報は他の情報と照合して個人に結び付く場合があります。利用許可を得た環境で使い、利用目的や閲覧権限、保存期間について組織の規程と適用法令を確認してください。第三者の通信内容の収集や無断追跡を行う構成は別途法的な検討が必要です。[個人情報保護委員会の通則ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)

### サンプルの種類

- **カナリアファイル:** HTML、PDF、TXT、JSON、CSV、Excel、PowerPoint、SQLite、`.env`などから形式と用途を選びます。ダウンロード名は対策に合わせた`Physalia_*`形式で、文書タイトルも自動で決まります。文書の架空データは25件です。`.env`は件数を使いません。カナリアURLの配置先は生成結果に表示します。通常のレコード形式では項目名とレコード番号、`.env`では設定キーを確認できます。複合アーチファクトでは配置例と運用者用インベントリを確認してください。
- **ランサムウェア・デコイフラッド:** 4〜8個の架空ファイルと、変更・削除時に架空ファイルを補充するスクリプトを別々に作ります。Python 3.11以降が必要です。補充は既定で無制限です。暗号化の停止や復元は行いません。
- **パス・メイズ:** 有限の通常フォルダーに架空ファイルを分散したZIPを作ります。攻撃がデコイを探索・暗号化する場合、処理が増えます。並列処理では実ファイルが先に処理される場合もあります。
- **スパース・デコイ:** 見かけ上大きな架空ファイルを配置先で作るスクリプトを作ります。コピーやバックアップ、同期では見かけのサイズ分の容量と時間を使う場合があります。
- **スタティック・デコイ・ポータル:** 用途とタイトルを設定します。配置用ZIPにはHTMLと架空文書が含まれ、ログイン機能はありません。
- **デコイ・データベース:** 顧客、売上、ユーザー管理などの雛形を選び、件数と項目を確認します。実カード番号やCVVは含まず、パスワードやAPIキーの見本は認証に使えません。既存DBには接続しません。
- **エンクリプテッド・ディープ・ネスト、ディレクトリ・メイズ、エンコーディング・メイズ:** 説明と見積もりを読み、サイズ・階層・件数を調整します。運用者専用ファイルは配置物と分けて保管してください。
- **説明のみの手法:** 「説明のみ」とある手法は考え方の紹介で、サンプル生成や本番環境の変更は行いません。

生成物は架空データで、ブラウザーから保存されます。アプリがWebサイトへ公開・配置することはありません。本番設定に投入せず、管理下の隔離環境で確認してください。

### ZIPとデータベースの確認

ZIPを展開して中身を確認します。スタティック・デコイ・ポータルやディレクトリ・メイズでは、展開後の`index.html`からページを確認できます。Webサイトとして使う場合は、自分が管理するテスト環境へ手動で配置します。DBは信頼できるSQLiteビューアで確認してください。エンクリプテッド・ディープ・ネストのZIPはそれ自体が暗号化されています。検証用パスワード一覧はデコイと分けて保管し、公開ディレクトリへ置かないでください。

### パス・メイズとスパース・デコイの使い方

パス・メイズのZIPを配置先に展開し、別の運用者専用JSONに記載されたファイル一覧を配置と撤去に使います。通常フォルダーと合成ファイルだけで構成され、リンクや常駐プログラムはありません。検索やバックアップが対象を巡る場合、追加のファイルを処理します。

スパース・デコイはZIPに作成スクリプトと説明書を収めます。ZIPを展開し、監視・配置先のPython 3.11以降で `py -3 create_sparse_decoy.py <既存の配置先>`（Windows）または `python3 create_sparse_decoy.py <既存の配置先>`（macOS/Linux）を手動実行します。生成時にはスクリプトは実行されません。作成後の名前と見かけのサイズは標準出力と運用者専用JSONで確認できます。既存ファイルは上書きせず、スパース形式を利用できない場合は作成を中止します。

見かけのサイズは1ファイルにつき1〜32 GiBです。実際の割り当ては作成時には小さくても、コピー・バックアップ・同期や暗号化結果の書き込みで見かけのサイズ分の容量を消費する場合があります。バックアップ対象からの除外を検討し、空き容量と同期先への影響を確認してください。部分暗号化やサイズでの除外、並列処理では追加の遅延が小さくなる場合があります。

### ランサムウェア・デコイフラッドの使い方

配置用ZIPを監視対象のルートに展開します。監視スクリプトは別の運用者専用ディレクトリに保存し、公開ディレクトリや配置ZIPの中には置かないでください。監視先のPython 3.11以降で、展開先を引数にして実行します（Windowsは`py -3 ransomware_tripwire_monitor.py <展開先>`、macOS/Linuxは`python3 ransomware_tripwire_monitor.py <展開先>`）。スクリプトは対象ファイルの内容を約1秒間隔で確認し、変更・削除・差し替えを`tripwire-alerts.jsonl`に記録します。監視と記録はスクリプトの起動中だけ行い、停止中のイベントは記録しません。ログはスクリプトと一緒に保護された場所へ保存してください。

変更を検知すると、同じディレクトリに別名の架空ファイルを補充します。既定では補充数・容量は無制限です。必要なら起動時に `--max-files 100` や `--max-bytes 1048576` を指定できます。上限は各起動中に補充したファイルとその内容にだけ適用され、既存ファイルや暗号化されたファイルの容量は含みません。再起動するとカウントは戻り、その前の起動中に補充したファイルは監視対象に引き継がれません。

ディスクが満杯になるとアプリやログ、復旧作業に影響します。既存ファイルの上書きは満杯でも可能な場合があります。攻撃が最初の一覧だけを処理する場合や並列に処理する場合、補充による遅延は生じないことがあります。補充プログラムの停止やディレクトリ削除でも補充できません。

この監視はファイルの読み取りや持ち出しを検知せず、プロセス停止、端末隔離、復元も行いません。監視開始前に変更済みの場合や、確認間隔の間に変更・復元された場合は検知できないことがあります。通常のアプリが書き換えない場所を選んで誤検知を減らし、既存のOS保護・EDR・書き込み権限管理と組み合わせてください。復元可能なコピーや履歴が一切ないデータは、破損後に元へ戻せません。

`.env.development`には、アプリ名、ログレベル、ポート、DB・Redis接続先、タイムアウト、再試行回数など、実運用でよく使われる設定項目を含めます。接続先は予約済み`example.invalid`の架空ホストで、認証情報は含みません。カナリアURLはコメント行に入り、ファイルを開くだけではアクセスされません。実アプリ設定には読み込ませず、隔離環境だけで使ってください。

## 2. 保存したファイルを確認する

ダウンロード名は対策に合わせて`Physalia_*`形式で自動設定されます。必要に応じて保存後にリネームしてください。ZIP内のファイル名は`.env`など形式上必要なものを保ちます。

ファイルはブラウザーのダウンロード先に保存されます。自動保存されない場合は、生成結果に表示されるファイル名リンクを押してください。HTMLは「新しいタブでHTMLをプレビュー」、PDFは「新しいタブでPDFをプレビュー」から内容を確認できます。単体HTMLは見た目のプレビュー用です。 Excel・PowerPointのカナリアファイルでは、対象の表セルに架空の通常URLを表示し、カナリアURLはハイパーリンク先にだけ保存します。監視先へ接続せずに確認するには、セルをクリックせず、右クリックしてリンク先を編集してください。セルをクリックすると監視先へ要求が送られる場合があります。カナリアファイルのHTML形式では、テキストリンク、ボタン風リンク、アイコン画像、次へボタン、ページ番号、ページ全体から誘導方法を選べます。いずれもクリックしたときだけアクセスし、ページ全体を選んだ場合はページ内のどこを押しても遷移します。ポータルの配置用ZIPには、ファイル一覧から文書を開ける`index.html`と`documents`フォルダーが入っています。ZIPを展開し、この2つを同じWebサイトのフォルダーに配置すると、監視URLを指定しない場合は一覧から6件の架空文書を開けます。監視URLを指定した場合は1件のリンクが監視先を向き、残り5件をページから開けます。HTMLプレビューを開くだけではカナリアURLへ接続しません。ページ内のカナリアリンクをクリックすると、監視サービスに記録・通知される場合があります。Webサイトへ自動配置はされません。カナリアファイルのプレビューは10件ずつ表示し、カナリアレコードがあれば該当ページを開きます。ページ送りで全件を確認できます。「データベース」手法のプレビューは先頭10件です。全件を調べる場合は、ダウンロードしたSQLiteファイルを手元で信頼しているSQLite対応ビューアで開いてください。`.env`のZIPを使う場合は、WindowsではZIPを右クリックして「すべて展開」、macOSではZIPをダブルクリックします。展開先にできる`.env.development`を確認してください。

メールアドレス表示スタイルでは、選ばれた1件のセルは通常のメールアドレスのままで、リンク先だけがカナリアURLになります。クリックするとブラウザーでURLを開き、メールは送信しません。

プロジェクト内に一時保管する場合は、リポジトリ直下の`generated/`に置くとGit管理から除外されます。除外設定だけに頼らず、公開前に`git status --short`で登録対象を確認してください。

### エンクリプテッド・ディープ・ネストのZIPを開く場合

ダウンロードされる`Physalia_*.zip`自体がAES暗号化された最初のZIPです。通常ZIPを先に展開する必要はありません。AES暗号化ZIPに対応した展開ソフトで開き、`*_zip_passwords.txt`にある該当パスのパスワードを入力してください。内側のZIPも同じ一覧でパスワードを確認して開きます。パスワード一覧はサンプル検証専用です。パスワードが含まれるため、デコイと一緒に配置・公開せず、アクセス制限された場所に保管してください。

## 3. 配置する場合

最初は本番環境ではなく、自分が管理する試験用サイトまたは別サーバーで試してください。これは、本番サイト・本番データベース・実際のユーザーアカウントから切り離した場所です。Webサイトで公開するファイルだけを配置し、本番の認証情報やデータは置かないでください。`.operator.json`や`.inventory.json`などの管理者専用ファイルは、Webサイトから誰でも取得できるフォルダーの外に保管してください。生成物には入力したカナリアURLが含まれる場合があるため、公開GitHubリポジトリへ登録しないでください。ログイン制限、HTTPS、アクセス記録、通知先は配置先で設定します。
