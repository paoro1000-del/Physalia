# AiDeceptionGuard

[English](READM.md) | 日本語

個人開発者や小規模組織向けの、ローカルで動作するデコイファイル生成ツールです。現在は初期プロトタイプです。管理権限のある環境で、配置・検知・対応を検証するために利用してください。

侵入後の探索や、持ち出された情報の確認・利用に対して、本物らしい偽情報による欺瞞と攻撃者の遅延を狙います。デコイの取得・使用を記録できれば対応の手掛かりにもなりますが、侵入や本物の流出を防ぐ保証はなく、通知が持ち出し前に届くとは限りません。AI、人間、スクリプト、並列・オフライン処理を含め、対象環境で効果を検証してください。

## まずは使ってみる

- GitHubの緑色の **Code → Download ZIP** からZIPをダウンロードして展開します。Gitを使う場合はクローンしても構いません。以下の起動スクリプトは展開・クローンしたフォルダー内にあります。
- Python 3.11〜3.14が必要です。起動スクリプトは3.14、3.13、3.12、3.11の順に確認します。Windowsでは[`start_windows.bat`](start_windows.bat)、macOS/Linuxでは`sh start_unix.sh`を実行してください。初回は仮想環境を作成し、固定・検証済みの依存パッケージをインストールして起動します。Pythonの導入方法は[はじめてガイド](docs/quickstart_ja.md)を参照してください。
- 初めてなら、画面上部の「最初のサンプル」で作成できます。初期値は「サービス管理」の架空レコード25件を含む単体HTMLファイルです。作成後、生成結果のプレビューリンクから確認できます。Webサイトとして配置する場合は「サンプルWebページ（HTML＋配置用ZIP）を作成」を選びます。ポータルは運用・共有ドキュメント・業務アーカイブ・記録管理の用途を選べます。配置用ZIPは自動保存され、ZIPには`index.html`と、ページから開ける架空PDF・Excel・CSVが6件入ります。.envのサンプルはデコイ専用です。実アプリや本番設定には読み込ませず、隔離した検証環境だけで使ってください。DBはプリセットを選ぶと、作成する項目と架空レコード数を確認できます。
- 生成物はローカルに保存され、自動配置はされません。画面上部の「監視サービスのURLを追加」を開き、監視サービスが発行したHTTPS URLを入力すると、次に作る対応サンプルへ反映されます。生成器はURLへ接続しません。URLを指定しない場合は通知されず、ファイルを作成・ダウンロード・閲覧しただけでも通知されません。配置後にクローラーやリンクプレビュー、利用者がURLへアクセスすると、監視記録が発生する場合があります。

## できること

- **ログの記録と手動確認**：デコイ接触後に記録する項目、個人情報への配慮、既存のログ基盤での確認手順を[ガイド](docs/log-review-guide_ja.md)にまとめています。利用者の既存ログを取り込んで自動判定する機能はありません。
- 生成物はローカルに保存され、自動配置はされません。画面上部の「監視サービスのURLを追加」を開き、監視サービスが発行したHTTPS URLを入力すると、次に作る対応サンプルへ反映されます。生成器はURLへ接続しません。URLを指定しない場合は通知されず、ファイルを作成・ダウンロード・閲覧しただけでも通知されません。配置後にクローラーやリンクプレビュー、利用者がURLへアクセスすると、監視記録が発生する場合があります。
- **エンクリプテッド・ディープ・ネスト**：AES暗号化ZIPを多層・分岐構造にし、選択形式を中心に架空ファイルと任意のカナリアを配置。パスワードは各ZIP用に生成します。持ち出し後の解凍・選別に手間を生じさせ、別に回収した本物の暗号化ファイルまで疑わせることも狙いますが、効果は未検証です。生成物に本物の秘密は入れません。ネストや迷路の業務シナリオでは、単独DB用14種類のうち12種類のスキーマを使います。売上・ユーザー管理の2種類は単独のデコイDBで選べます。
- 生成物はローカルに保存され、自動配置はされません。画面上部の「監視サービスのURLを追加」を開き、監視サービスが発行したHTTPS URLを入力すると、次に作る対応サンプルへ反映されます。生成器はURLへ接続しません。URLを指定しない場合は通知されず、ファイルを作成・ダウンロード・閲覧しただけでも通知されません。配置後にクローラーやリンクプレビュー、利用者がURLへアクセスすると、監視記録が発生する場合があります。

- **スタティック・デコイ・ポータル**：プレビュー用HTMLと、架空PDF・Excel・CSVを6件含む配置用ZIPを生成。監視URLを指定しない場合は一覧から6件を開けます。指定した場合は一覧の1件が監視先へのリンクになり、ほかの5件をページから開けます。
- **フェイクトラップ**：異常アクセス、通報済み、認証中スピナーの静的HTMLを生成。表示のみで、実際の検知・通報・認証や外部通信は行いません。アクセス監視と通知は配信側で別途設定します。
- **技術紹介**：データ・ディルーションは、本物と大量の合成レコードを混ぜ、流出後の選別・利用を難しくする構想です。プリビレッジ・ハニーワード・セッションは、登録済みの偽パスワードに一致した場合に隔離デコイへ誘導する構想です。どちらも説明のみで、本番DBの変更や認証連携は実装していません。
- **インフィニット・ストリーム**：認証付きの終端のない配信サーバーを、設定・起動説明とともに生成。
- **ディレクトリ・メイズ**：有限の階層・分岐・任意の相互リンク・架空ファイルを含む静的配信用ZIPを生成。動的に変化するURLやHTTPリダイレクトは拡張案であり未実装です。
- **エンコーディング・メイズ**：業務シナリオに合った複数の架空ファイルをBase64・Hex等で多段変換したZIPを生成。

デコイDBは、持ち出された後に候補の真偽を判断しにくくし、照合に費やした作業が結論に至らないことも狙います。偽DBを本物として転売した場合の売り手の信用への影響も仮説です。真偽確認の難しさや信用への影響は未測定で、本物のDBが別途流出する可能性は残ります。

生成したファイルはブラウザーのダウンロード先に保存されます。配置先への自動アップロードは行いません。配置先へ移す前に、ダウンロードした配置用ファイルと管理者専用ファイルをリポジトリ外、またはGit管理対象外の `generated/` に保管してください。`.gitignore`はリポジトリ直下の生成用JSON・TXT・HTML・CSV・PDF・PowerPoint・Excel・DBファイルを除外しますが、一般形式の除外は直下に限られます。サブディレクトリに置いた生成DBや文書は追加候補になり得ます。`.operator.json`・`.inventory.json`と通常の`.env`類は場所を問わず除外しますが、`.env.example`は例外として追跡可能です。除外設定だけに頼らず、コミット前に `git status --short` を確認し、実データ、秘密、パスワードやカナリアURLをGitへ入れないでください。

攻撃者側にもデコイを見分けるAIや手順がある前提で評価します。2026年の[Rouxiiプレプリント](https://arxiv.org/abs/2609.26555)は、特定の評価でデコイ識別率が19%から97%に上がった比較と、個別のOT用ハニーポットへの妨害を報告しています。これは本ツールの有効率を示すものではありません。デコイを本番系から隔離し、資源上限を設け、ログを保全してください。詳しくは[多角評価](docs/deception_evaluation.md)を参照してください。

## 準備と起動

GUIでは一度に一手法を選び、想定する侵入・流出の場面、仕組みの流れ、効果が期待できる条件、限界と検知・対応の準備を確認できます。詳細説明と法的な見解は開いて確認できます。エンクリプテッド・ディープ・ネストは、選択した手法内で意図的に複数形式のデコイを作る機能です。[配置・検知・対応ガイド](docs/deployment_ja.md)では実装済み機能と、本番連携が必要な部分を一覧化しています。GUIからガイドと連携サンプルZIPを開けます。

手法カードには狙う役割として「検知」「遅延」「デコイ誘導」「流出後の攪乱」「AI攻撃を想定」のタグを表示します。複数タグは複数の狙いを表し、AIに限った有効性や検知・遅延の保証ではありません。通知・監視には別途設定が必要な手法があります。

各手法の説明には、日本の不正アクセス禁止法と米国の連邦法・州法について一般的な見解と注意点を記載しています。[各手法の法律上の説明](docs/legal_ja.md)には根拠と追加の考慮事項もまとめています。いずれも一見解であり、導入前に適用地域と構成に詳しい法律の専門家へ確認してください。

「設定を保存」で形式・件数・DB項目などをJSONに保存できます。カナリアURL欄とURL形式の入力値、所有確認チェックは保存しません。隔離デコイ用ドメイン欄に入力したドメイン値はJSONに残りますが、所有確認チェックは読み込み後にやり直します。カスタム項目名や自由入力の候補値も保存されます。**自由入力欄に書かれたURLや秘密情報を自動で削除する機能はありません。** 実データや秘密を入力せず、設定JSONは管理者専用として保管してください。

保存・読み込み時は、一般的な認証情報やカード番号など一部の形式を拒否しますが、自由入力欄のURLは検査しません。生成時は自由入力の未承認URL・メール・公開ドメイン・IPアドレスなどを検査し、カナリアURLと所有確認付きドメインは専用欄で別途検証します。これらは限定的な形式検査であり、すべての秘密情報や接続先を検出する保証はありません。架空接続先には `example.invalid` を使ってください。過去に保存した設定は、画面の項目構成やバージョンによって読み込めない場合があります。

すべての生成物に、設定・SHA-256・カナリアURLの配置数と未使用数・配置先や担当者の記入欄を含む `*.inventory.json` を別途出力します。カナリア文脈を自動選択した場合は、実際に選ばれた用途・項目名・表示文言も記録します。配置用成果物と既存の `*.operator.json` のハッシュも記録します。転送後はアクセス制限された保管先に置いた台帳と照合してください。台帳自体を同じ経路で置き換えられた場合、ハッシュだけでは検知できません。台帳は管理者専用で、配置用ZIPには含みません。operatorファイルとともに別リンクから保存してください。台帳は撤去や見直しに使えますが、トークンの自動失効は行いません。 台帳自身のファイル名は`inventory_file`で確認できます。台帳自身のハッシュは自己参照になるため含まれません。`operator_files`と`operator_artifacts`には、その台帳以外の管理用付属ファイルが記録されます。

ソースの最低要件はPython 3.11です。起動スクリプトとCIはWindows・Ubuntu・macOS上のPython 3.11〜3.14に対応しています。Python 3.15はCI対象外で未検証です。`requirements.txt` と `requirements-dev.txt` は直接依存・間接依存の版を`==`で固定し、配布ファイルのSHA-256ハッシュも記載しています。導入時は `--require-hashes --no-deps --only-binary=:all:` を使います。`--only-binary=:all:`で事前ビルド済みwheelのみを許可します。`--no-deps`だけではソース配布物の隔離ビルド依存まで固定されません。対応wheelがない場合はフラグを外さず、配布元・ビルド要件・対象環境を確認してください。pipは選択したwheelのハッシュを照合し、未記載の実行時依存を自動解決しません。この照合は、信頼できるコミットまたはリリースから取得したrequirementsファイルを前提に、配布ファイルの差し替えを検出します。承認済み配布物に含まれる悪意あるコードや、版・ハッシュの未レビュー変更は検出できません。ロックファイルの変更をレビューし、利用可能な場合は署名付きコミット・タグやパッケージの来歴情報も検証してください。CIではインストール後に`pip check`を実行し、浮動版・ハッシュ未指定の依存を拒否して、PyPIの既知の脆弱性情報を照合します。この照合はPyPIの情報にない問題やネイティブライブラリの脆弱性を検出しません。依存を更新する際は配布元とパッケージ内容を確認し、版とハッシュを明示的に更新してからプロジェクトの確認を実行してください。以下はWindows PowerShellでの例です。

Windowsで簡単に起動するには、リポジトリ内の [`start_windows.bat`](start_windows.bat) をダブルクリックしてください。Python 3.14・3.13・3.12・3.11の`py`ランチャーを優先し、なければ対応する`python`または`python3`コマンドを探して`.venv`を作成します。初回と`requirements.txt`変更後だけ、ハッシュ検証付きで固定済み依存関係をインストールします。不足している固定済みパッケージを取得するため、インターネット接続が必要な場合があります。既存パッケージを最新版へ更新することはありません。ブラウザーが開き、停止時は起動した黒い画面で`Ctrl+C`を押します。標準ポートが使用中の場合は、`start_windows.bat --port 8766`のように別ポートを指定してください。

```powershell
python -m venv .venv
.\.venv\Scripts\python -m pip install --require-hashes --no-deps --only-binary=:all: -r requirements.txt
.\.venv\Scripts\python app.py
```

macOS/Linuxで簡単に起動するには、`sh start_unix.sh`を実行してください。Python 3.14・3.13・3.12・3.11の版指定コマンドを探し、なければ対応する`python3`または`python`を確認して`.venv`を作成します。初回または`requirements.txt`変更後だけ固定済み依存関係をハッシュ検証付きでインストールして、ブラウザーを開きます。不足するパッケージを取得するためインターネット接続が必要な場合があります。依存関係を最新版へ自動更新しません。停止はターミナルで`Ctrl+C`です。標準ポートが使用中の場合は、`sh start_unix.sh --port 8766`または`start_windows.bat --port 8766`のように別のポートを指定してください。

macOS/Linuxでは仮想環境のPythonを直接実行します。

```sh
python3 -m venv .venv
.venv/bin/python -m pip install --require-hashes --no-deps --only-binary=:all: -r requirements.txt
.venv/bin/python app.py
```

表示された `http://127.0.0.1:8765/` をブラウザーで開いてください。停止はターミナルで `Ctrl+C` です。ポートを変更するには `python app.py --port 8766`、OSの空きポートを利用するには `--port 0` を指定します。macOS/Linuxでは仮想環境の実行ファイルは通常 `.venv/bin/python` です。

画面右上の「言語」で日本語と英語を切り替えられます。選択はブラウザーに保存され、生成するWeb画面にも反映されます。コマンドの表示を英語にするには、起動時や復号時に `--lang en` を指定します（例：`python app.py --lang en`）。既定は日本語です。

## ログの記録と手動確認

カナリアURLへの要求は接触の手掛かりですが、誰がファイルを読んだかや侵害を証明するものではありません。収集項目を絞り、既存のWebサーバー／監視サービスのログを権限のある担当者が確認してください。JSON Linesの例、確認手順、個人情報上の注意は[ログ記録ガイド](docs/log-review-guide_ja.md)を参照してください。ログ取込・自動分析機能はありません。

定期的な認証・クラウド監査の確認は、組織がすでに利用しているID基盤やログ管理サービスで行ってください。本ツールにはログ取込・自動分析・検知ルールはありません。

## カナリアの動作

カナリアURLへアクセスが届くと、URL発行元やホスティング事業者には、通常、送信元IPアドレス・アクセス時刻・User-Agentなどのリクエスト情報が渡ります。実際に保存される項目、保存期間、保管国はサービスごとに異なります。IPアドレスだけで攻撃者本人を特定できるとは限らず、VPN・踏み台・クローラー経由の可能性もあります。利用前に提供元のプライバシー通知、ログの閲覧者・保存期間・削除方法、委託先や保管地域を確認し、URLに顧客IDなどの識別情報を含めないでください。アクセス情報は他の情報との照合状況によって個人情報または個人関連情報に該当し得ます。個人情報保護委員会は、個人を識別できない端末識別子等も個人関連情報に該当し得ると説明しています（[通則ガイドライン](https://www.ppc.go.jp/personalinfo/legal/guidelines_tsusoku/)）。

監視先のURLは、既存のカナリアサービス等で利用者が別途取得して入力します。このアプリにカナリアサービスの発行・受信・通知機能はありません。URLを省略した場合、`.env` 形式には無効な `example.invalid` の例示URLを入れますが、他形式ではURL欄を省略します。どちらも監視先にはならず、**通知は発生しません**。

持ち出されたファイル内のURLが後から実際に要求され、監視先に届けば、接触を調査する手掛かりになります。踏み台・VPN・サンドボックス経由では観測されたIPが攻撃者本人を示すとは限らず、ファイルの拡散後は第三者やスキャナーによる要求も混ざります。配置先とURLの対応を管理者専用台帳に保管し、既知のスキャンや他のログと照合してください。通信が遮断されたりURLが試されなかったりすれば通知されません。

リンクを読むクローラーやAIエージェントがアクセスする場合に備え、カナリアURLには公開到達可能な監視先を指定してください。非公開IPアドレス、`localhost`、`.local`・`.internal` などの内部用ホスト名、単一ラベルのホスト名は受け付けません。DNS解決は行わないため、入力したドメインが内部アドレスへ解決されないことは配置環境で確認してください。

単体の生成ではURLを1つ指定します。暗号化ネスト、ディレクトリ・メイズ、エンコーディング・メイズではURLを1行ずつ最大400件まで指定でき、カナリアの発火先と配置ファイルの対応を管理者専用台帳に記録します。生成後の画面には配置数・使用した異なるURL数・未使用URL数を表示します。生成されたカナリア配置先の数だけURLを使い、割り当て時は指定URLを一度ずつ使ってから再利用します。配置先よりURLが多い場合、余ったURLは使われません。再利用URLが発火しても、通知から接触先ファイルを特定できません。暗号化ネストは指定率で一部のファイルに配置するため、デコイの件数や配置率によっても未使用URLが残ることがあります。

ファイルを読むだけではURL型カナリアは発火しません。PDF・Excel・PowerPoint・HTMLでは通常のリンク、設定・JSON・CSVでは接続先の値、DBでは接続先テーブルにURLを入れます。ファイルを開いたときの自動通信は行いません。通知には、そのURLへ実際にアクセスされる必要があります。実際の通知条件と遅延は利用するサービスに依存します。利用開始前にご自身でテストしてください。生成物に含まれるURLはトークンとして扱い、公開リポジトリにコミットしないでください。

カナリアファイルでは、URLの文脈としてサービス管理・請求・サポート・レポートを選択でき、項目名やリンク表示文言も指定できます。用途に応じて架空レコードの列と値も変わり、サービス管理はクラウド資産、請求は請求書、サポートは問い合わせ、レポートは売上明細のスキーマを使います。自動選択も利用できます。`.env`では項目名を大文字に、JSON・CSVでは指定した名前を使います。CSVの見出しには読みやすい表示文言と指定した項目名を併記し、URLは先頭レコードにのみ配置します。Excelでは用途に合わせたシート名のデータシート内にリンクを置きます。SQLiteでは用途別テーブルに保存し、PDF・PowerPoint・HTMLでは指定文言のリンクにします。テキスト形式では表示文言の横にURLを記載します。PowerPointでは指定件数をすべて収録し、最大10件ずつスライドに分けます。CSVは数式として解釈されうる文字列の先頭にアポストロフィを付け、スプレッドシートでの数式解釈を抑えます。そのためCSV上の元の文字列とは異なる場合があります。Excelは文字列セルとして保存し、数式やマクロは作成しません。

これはURLの**周囲の文脈**を調整する機能です。URL自体やPDF・Officeファイルのリンク先は解析でき、カナリアサービス固有のドメインやURL構造も識別の手掛かりになります。入力URLは変更せず、前後に空白がある場合は補正せずエラーにします。表示名だけで通知や識別不能性が保証されることはありません。URL未設定では実際の通知は発生しません。暗号化ネストとディレクトリ・メイズには、それぞれのシナリオに応じた文脈が適用されます。カナリアファイル用の個別設定は引き継がれません。

文書の内容・参照番号・氏名などは生成ごとに変わります。ファイル形式を変えることだけでデコイの識別を防げるとは限りません。生成物は本番の命名・文書構成に合わせて選び、配備前に開いて確認してください。

ファイル名を空欄にすると、形式に合った名前を自動で選びます。業務文脈の接頭語、運用上の状態・工程ラベル、日付接尾語を変えて、繰り返し生成した際の単調さを減らします（例：`customer_archive.db`、`quarterly_report_2026Q4.pdf`、`customer_export_v2.csv`）。名前の一意性や、見破られないことを保証するものではありません。指定した名前は変更しません。`.env`形式では通常のURL設定なら `.env`、切替メモ形式なら `.env.development` が既定です。環境名は変更できます。ファイル名を指定した場合は `指定名.env` になります。

通常の`.env`形式ではURLを一重引用符で囲みます。.env読込ツールごとに変数展開の挙動が異なるため（[python-dotenv](https://github.com/theskumar/python-dotenv#variable-expansion)、[Docker Compose](https://docs.docker.com/compose/how-tos/environment-variables/variable-interpolation/#env-file-syntax)）、`$`を含むURLはどちらの.env形式でも受け付けません。一重引用符を含むURLは開発・本番切替メモ形式なら利用できます。URL自体を書き換えることはありません。

ブラウザーによっては、直接ダウンロードするとファイル名先頭の `.` が削除されます。そのため、先頭が `.env` のファイルは、正確なファイル名を保持する配置用ZIPを自動でダウンロードします。ZIPを展開して配置してください。画面には直接保存用リンクも表示します。管理台帳JSONは別リンクで保存します。

### .envの開発・本番切替メモ

「開発・本番切替メモ」を選ぶと、次のように開発用URLを有効な設定行に、本番用に見えるカナリアURLをコメントに配置します。URLは例です。

```dotenv
# 開発環境用URL（ローカルAPI接続）
URL="http://dev.example.invalid:8080"

# 本番環境用URL（リリース設定）
# URL="https://監視サービスが発行したURL"
```

設定キー、有効な環境用URL、環境名、両方のコメントを編集できます。環境名は `APP_ENV` と既定URLのホスト名に反映されます（例：`staging` は `staging.example.invalid`）。URLを手入力する場合も選択した環境に合わせてください。開発環境の既定URLは `http://dev.example.invalid:8080` です。生成前に詳細設定の有効URLやコメントを確認してください。`example.invalid`以外のホストを入力する場合は、所有し、本番認証のない隔離検証先だけに向けていることをチェックで確認してください。URLをたどるクローラーやAIエージェントからリクエストを受ける可能性があります。生成器は名前解決・接続を行いません。内部・本番の接続先は使わないでください。確認は設定ファイルに保存されず、設定読込後は改めて必要です。通常形式で使う「URLを記載する文脈」の項目名や表示文言は、この形式には適用しません。発行されたカナリアURLを変更せず、値を引用符で囲みます。シェル展開につながる文字や改行を含む入力は受け付けません。

コメントを空欄にすると、生成ごとに開発環境・本番環境・リリース設定を示す組み合わせを選びます。既定文言はURLをカナリアとは呼ばず、AIへの指示も含みません。入力したコメントはそのまま使用します。

コメントは`.env`パーサーが通常無視するため、それを読む人やAIがURLを試す場合にだけ、カナリアサービスで通知され得ます。コメントを読んだだけ、ファイルをダウンロードしただけでは通知されません。一方、メール・文書スキャナーやリンクプレビューがURLを自動取得して通知が発生する場合があります。通知はURLへの要求を示すだけで、攻撃者やファイル閲覧者の特定にはなりません。提供元のUser-Agent等を既知のスキャンや配信側ログと照合してください。自動取得だけの探索者には配信側ログが別途必要です。カナリアURLのドメインやコメント内のURLそのものは解析可能です。生成物はデコイ専用の配置先に置き、本番アプリの設定として読み込ませないでください。

## ネストの構成とパスワード

GUIで次の設定ができます。

| 設定 | 内容 |
| --- | --- |
| 階層・分岐 | 1〜8階層、次階層への分岐1〜3本。暗号化ZIPは合計40個まで |
| ディレクトリ | ZIP内の深度1〜5を指定。フォルダー名は用途別の候補が初期表示され、編集も可能 |
| ダミー | 各ZIPに0〜10ファイル。形式混在時は選択した主形式を約75%にし、残りを重み付きで変化 |
| カナリア | 各ダミーに0〜100%の確率でURLを埋め込み。0%またはURLなしなら監視用URLを配置しない |
| パスワード | 単語ベース／完全ランダム、小文字・大文字・数字・記号、4〜64文字の範囲、単語候補を指定 |
| 復元メモ | 鍵台帳が別にあるよう示す任意のデコイ。実際のパスワード文字は含めない |

パスワードの手入力は不要です。各ZIPに異なる値を割り当てます。単語形式は単語を基礎にランダムな英字・数字・記号をランダムな位置へ加え、固定された年号・末尾パターンを避けます。候補が重複した場合は同じ長さ・文字種のランダム方式へ切り替えて一意にします。復元メモは、攻撃者に別の鍵台帳を探させるための任意のデコイで、実際のパスワード文字は含みません。文面は複数の業務メモ形式から選び、同じ定型文の繰り返しを減らします。設定した伏せ字数はメモの文面だけを変え、パスワードの一部を公開したり探索量を減らしたりしません。パスワード本体は管理者専用JSONにのみ保存されます。既定の9〜13文字と「序盤は短く、深い階層ほど長くする」設定では、深い階層ほど長くなります。ZIP取得後はオフラインで並列試行できるため、解読成功も遅延時間も保証できません。完全ランダム方式も検討してください。**9〜13文字でも現実的に解読できるとは限りません。** 解読時間はZIP形式、攻撃設備、手掛かりなどに左右され、保証できません。手掛かり自体が不自然なら疑われるため、配置先の運用に合わせて省略できます。

生成後は、次の3ファイルを保存します。ZIP内の各エントリー日時は生成時点から過去180日以内で個別に設定します。これは実ファイルの作成履歴を示さないため、監査証跡や時系列の根拠には使わないでください。

1. `名前_deployment.zip`：配置用。通常の配送用ZIPの中に、AES暗号化した外側のZIPと、選択した場合は序盤の保守メモが入ります。その先にダミー文書と次階層の暗号化ZIPがあります。
2. `名前.operator.json`：画面の別リンクから保存する**管理者専用ファイル**。全ZIPのパスワード、階層、内部パス、手掛かりメモの配置先、カナリア配置先、各パスワードの生成方式、各文書の形式を記録します。
3. `名前_deployment.zip.inventory.json`：生成物のハッシュ、設定、カナリアURLの情報、形式別件数などを含む運用台帳です。これも管理者専用として扱い、配置用ZIPと分け、アクセス制限された場所に保管してください。公開・配置しないでください。2つのJSONを安全な場所に保存してください。画面は管理者専用ファイルをすべてダウンロードしてから確認できるようにし、未確認のままページを閉じる場合や、手法の切替・設定読み込み・再生成でリンクを消す場合に警告します。

暗号化ZIPはAES対応のZIPツールで確認してください。AES非対応の展開機能では開けません。管理者専用JSONは配置用ZIPに含まれません。ファイル名やフォルダー名は通常のZIPと同様に一覧から見えます。形式混在を有効にすると、選択した主形式を約75%に保ち、残りを重み付き抽選でExcel・SQLite・.envなどにします。この設定は暗号化ネスト内のダミー文書に適用されます。形式別件数は `*.inventory.json` と `.operator.json` の `format_counts` に、個々の文書形式は `.operator.json` の各文書の `format` に記録されます。カナリアURLの配置もファイルごとに抽選されるため、少数では設定率と実際の割合が異なる場合があります。対象となる全ダミーにURLを入れる場合は100%を選んでください。

暗号化ネストの生成は有限で、ダミー本文の非圧縮サイズ合計は32MiB、暗号化ZIPの累積サイズと配置用ZIPはそれぞれ64MiB以内です。入れ子によるサイズ増幅が大きい構成は生成を中止します。終端のない配信は別項目のインフィニット・ストリームで扱います。防御効果や攻撃者の拘束時間は生成処理のテストとは別に評価が必要です。

以前の独自ADG形式は新規生成せず、既存ファイルの確認に限り `python decrypt.py 入力.adg 出力.json`（英語表示は `--lang en`）を残しています。通常ファイルのみを読み込み、入力は64MiBまで、既存の出力ファイルは上書きしません。POSIXでは出力を所有者のみ読める権限で新規作成します。Windowsでは出力先フォルダーのACLを継承するため、フォルダーを制限して `icacls` で実効権限を確認してください。復号したファイルは機密情報を含む可能性があるため、公開リポジトリや共有フォルダーに置かないでください。新しいZIPには使用しません。

## デコイDBの項目設定

生成時には自由入力に含まれる未承認のURL・メール・公開ドメイン・IPアドレスと、一般的な認証情報・秘密鍵・JWT・Luhnチェックを通るカード番号形式を拒否します。発行済みカナリアURLと所有確認付きデコイドメインは専用欄で別途検証します。`example.invalid` などの予約済み例示値は使用できます。設定の保存・読み込み時にも、自由入力の一般的な認証情報・秘密鍵・JWT・Luhn検査を通るカード番号形式は拒否しますが、URL検査は生成時に行います。いずれも形式ベースの限定的な検査で、接続先・秘密情報・個人情報を網羅的に検出するものではありません。実データや秘密は入力せず、設定JSONを安全に保管してください。

用途別テンプレートから顧客、カード台帳、企業、パスワード保管庫、注文、売上明細、請求、従業員、ユーザー管理、API認証情報台帳、取引先、問い合わせ、在庫・資産、クラウド資産を選べます。テンプレートを選ぶとテーブルと項目が入れ替わり、その後に自由に編集できます。「カスタム」に切り替えて「項目を追加」から最大30項目を定義することもできます。連番・氏名・メール・会社・部署・整数・小数・日付・日時・状態・UUID・電話・ドメイン・通貨・テスト用参照値などに対応します。会社・部署・状態・テキストは `active|pending|archived` のように候補値を、整数・小数は `100,5000` のように範囲を指定できます。テーブル名と項目名は英字または `_` で始まる英数字と `_` の48文字以内です。API認証情報台帳はサービス・担当者・権限範囲・ローテーション履歴を含み、キー見本は認証に使えない架空値です。ユーザー管理プリセットは表示名とログイン名を別列で生成し、ログイン名は架空値です。実際に認証に使える情報は含みません。日本語UIでは商品・業種・役割・クラウドサービス・環境名など人が読む候補値も日本語で生成し、テーブル名・項目名と一部の状態値は連携しやすい英語表記を保ちます。クラウドの接続先ドメインは英字スラッグと予約済み`.invalid`を使います。カスタム項目では、請求書番号・注文番号・売上番号型も選べます。
日本語画面では氏名・会社名・部署名に日本語の架空値を使い、メールアドレスは対応するローマ字表記を使います。会社名がある行では会社名に合わせた予約済み `example.invalid` 配下のドメイン、会社名がない行では `example.invalid` を使います。英語画面では英語の候補値を使います。

デコイらしさを抑えるには、会社・部署・状態・テキスト型の候補値を、組織の業務用語に合う架空の値へ編集してください。氏名やメールも候補から選ばせる場合は、型をテキストに切り替えます。候補値には実在ドメイン・IPアドレス・URL・メールを入力できません。会社名がある行のメール・ドメイン型は会社名に合わせた `.invalid` 配下の値を使い、会社名がない行は `example.invalid` を使います。専用欄で隔離デコイ専用の所有ドメインを指定した場合はその値を使います。
自然さを高める場合は、所有し、隔離デコイ専用にしたドメインを指定できます。生成器はDNS照会もメール送信もしません。所有確認にチェックが必要です。本番メールドメインや実メールボックスは使わず、受信メールは隔離した監視用シンクだけに配送してください。

請求書テンプレートでは、請求状態に合わせて発行日と支払期限も生成します。たとえば未払い状態では期限を将来に、期限超過では発行日より後かつ過去の日付にします。注文テンプレートでは、保留・処理中は最近、出荷済み・完了はそれより前の日付になりやすいよう、注文状態と注文日を連動させます。問い合わせテンプレートは「open」「pending」「in_progress」「resolved」「closed」の状態を使い、未解決案件が比較的新しくなるよう受付日時を合わせます。従業員テンプレートは「onboarding」「active」「on_leave」「offboarded」を使い、入社日を状態に合わせて生成します。

Excel（XLSX）は生成文字列を文字列セルとして保存します。CSVにはセル型の情報がないため、数式に見える値の先頭に `'` を付けて数式として解釈されるリスクを下げます。この `'` はCSVデータに残ります。CSVの取り込み方は表計算ソフトによって異なるため、利用するソフトで確認してください。

カード台帳はブランド・名義・期限・状態を含みますが、カード番号欄には決済に使えない `TEST-NOT-A-PAN-...` 形式の参照値を置き、PANやCVVは作りません。状態が `expired` の場合は期限を過去に、`active` または `suspended` の場合は将来にして、台帳内の値を整合させます。パスワード保管庫はサービス・ユーザー名・保管グループを含み、通常の`password`列にランダムな合成文字列を置きます。`login_url` は `https://.../login` 形式にしますが、接続されない予約済みの `.invalid` ドメインを使います。実在アカウントや認証サービスには結び付かず、実認証情報やハッシュを取り込みません。会社・取引先テンプレートのドメインは、英語名と内蔵の日本語社名には読みやすいASCIIスラッグ、日本語などの任意社名にはIDNAラベルを `.invalid` 内に生成します。同じ会社名には同じドメインを割り当て、長い社名はラベル長の上限内で区別できるよう調整します。メール・ドメインは安全な `.invalid`、クラウド資産例のIPは文書用アドレス帯です。架空の値でも本番へ誤投入されないよう、デコイ専用領域に置いてください。
GUIで管理下のデコイ用ドメインを指定すると、保管庫の通常 `login_url` を `https://サービス名.指定ドメイン/サービスに応じたログインパス` にできます。生成器はDNS解決・接続をしませんが、攻撃者やクローラーがURLを開くとそのドメインへ接続します。所有するドメインを入力し、明示確認を付け、一致するTLS証明書を用意し、ワイルドカードDNS等を本番認証のない隔離デコイだけに向けてください。このURLはカナリアトークンではないため、DNSまたはWebサーバーのログで接触を監視してください。単独DB・暗号化ネスト・ディレクトリ・メイズ・エンコーディング・メイズの非`.env`形式で同じ設定を使います。`.env`では環境変数に反映されます。空欄なら予約済み `.invalid` のままです。

DBにカナリアURLを指定すると、通常は接続先テーブルへ保存します。パスワード管理テンプレートでは、`login_url`列がURLを格納できる型（ドメインまたはテキスト）なら、URLをランダムに選んだ1件へ配置し、レコード番号を管理者専用台帳に記録します。列が削除・改名されている場合や別の型に変更されている場合は、接続先テーブルに保存します。URLへ実際にアクセスされた時だけ通知され、DBの読み取りだけでは通知されません。id列は主キーにし、メール・ドメイン・状態などの検索項目に索引を付けます。実データの取り込み、SQLの実行入力、複数テーブル間の関連、既存スキーマの自動複製は未対応です。ネストやメイズ内の文書・DBは選択した業務シナリオに対応する架空データを使い、単独のDB生成画面のカスタム項目設定は引き継ぎません。

### インフィニット・ストリーム

無効なバックエンドBearer認証は、各範囲（`stream` / `admin`）・HTTPメソッドの組み合わせごとに、最初の失敗を即時出力し、その後は最大10秒間隔で抑制分を集約します。後続の失敗がなくても、タイマーが最大10秒後に累積失敗数の増分を出力します。イベントには累積失敗数を含みますが、資格情報・経路・接続元IP・クライアント指定request IDは含めません。Nginxが拒否したBasic認証失敗はPythonサービスに届かないため、保護されたNginxまたはゲートウェイログで確認してください。

配信サーバーは配信イベントと、配信または認証済みHEADの成功応答に相関用の `request_id` を付けます。付属Nginx例は要求ごとにIDを生成し、上流へ転送し、完了時のJSONアクセスログにも記録します。ログ基盤ではサーバーイベントとNginxログを `request_id` で突合し、開始・終了イベント同士はさらに `run_id` と `stream_id` で対応させてください。Nginx通常アクセスログは応答完了まで遅れるため、即時検知は `stream_started` イベントを使います。

管理者専用JSONで起動する場合、POSIXではファイル権限を所有者のみに制限してください（`chmod 600`）。権限が広いとサーバーは起動を拒否します。WindowsではACLを自動検査しません。ファイルと親フォルダーへのアクセスを制限し、`icacls`で実効権限を確認してください。このJSONには配信用と管理用の両トークンが含まれます。

速度上限は全接続の合計で、累積配信量の上限ではありません。連続配信時の理論上限は `速度(KiB/秒) × 84.375 = MiB/日` です。既定の8 KiB/秒では約675 MiB/日、最大64 KiB/秒では約5.27 GiB/日になります。HTTP/TCP等の通信量は別途加算されます。配備前に回線・クラウド費用を見積もり、帯域監視と停止手段を用意してください。

バックエンドは`127.0.0.1:9080`で待ち受けます。任意の認証付きNginx例は`127.0.0.1:9082`で受け付けて9080へ転送します。同一ホスト上のTLSゲートウェイは9082へ接続できます。別ホストのゲートウェイを使う場合は、NginxをプライベートIFにだけ束縛し、接続元をそのゲートウェイに限定するファイアウォールを設定してください。公開ネットワークへ直接さらさないでください。

インフィニット・ストリーム用Nginx例には、送信元IPごとのリクエスト制限（毎分10件、バースト5件）も含まれます。再接続や共有NATの利用者数に合わせて調整してください。Nginxの前段にプロキシがある場合、信頼済みプロキシだけにreal-IP設定を行ってください。任意の転送ヘッダーを信用すると、制限を回避されたり他の利用者まで巻き込んだりします。

配信形式（SQL・CSV・テキスト）、パス、ポート、**全接続合計**の速度（1〜64 KiB/秒）、同時配信数（1〜8）を指定します。パスは `/` 区切りのASCII英数字・`_`・`-`・`.`で指定し、`..`、`.`だけのパス要素、`.`で終わるパス要素は使用できません（最大160文字）。配信中の応答に総時間・総容量での終了はありません。ただし、バックエンドのソケットが5秒間無通信になると接続を終了し、受信側が読み取らず書き込みが詰まった場合も対象です。クライアント切断・管理者の停止・障害等でも終了します。ファイルとして事前に無限データを作る構成ではなく、接続中に少量ずつ生成します。行IDは増加しますが、参照値と金額は各行ごとに独立して生成する架空値です。

例としてGUIでファイル名を `stream_sample` に設定した場合は、ZIPを専用フォルダーへ展開し、管理者用JSONをその外に置いて起動します。

```powershell
Expand-Archive -LiteralPath .\stream_sample_deployment.zip -DestinationPath .\stream_sample
python .\stream_sample\serve.py --operator .\stream_sample.operator.json
```

CLIの表示を英語にする場合は、起動コマンドに `--lang en` を追加してください。既定は日本語です。

Python標準ライブラリだけで動き、`127.0.0.1:9080`（既定）で待ち受けます。サーバーソースを含む配置用ZIPにはApache-2.0のLICENSEも同梱します。配信URLへは管理者用JSONの `ADG_STREAM_TOKEN` を `Authorization: Bearer ...` ヘッダーで渡します。プロセス終了は `Ctrl+C`で行います。配信のみを停止して管理経路を残すには、別の `ADG_STREAM_ADMIN_TOKEN` で `POST /stop` を使います。停止後は再起動まで新規配信も拒否しますが、プロセスと管理用エンドポイントは稼働したままです。`GET /health` は管理用トークンで現在の`run_id`・稼働数・開始数・プロセス起動後の`payload_bytes_sent`を返します。カウンターは再起動でリセットされるため、複数起動分は`run_id`ごとに集計してください。終了イベントも同じ名前で個別配信量を記録します。 認証済みのHEAD要求は本体を配信せず、stream_probeイベントを記録します。配信枠を消費しません。終了イベントの`reason`は運用者停止、受信側切断、書き込みタイムアウト、通信・処理エラーの大まかな分類です。これは根本原因の診断ではありません。 各イベントには起動ごとに変わる `run_id` を含めます。配信開始・終了イベントの相関には、同じ起動内で連番となる `stream_id` も使ってください。`payload_bytes_sent`はデータ本体のみのバイト数で、HTTP/TCPのヘッダーや通信制御分を含みません。終了イベントの`duration_ms`はサーバー側で計測した接続継続時間で、クライアントが全バイトを受信した保証ではありません。トークンはZIPに含まれず、環境変数から指定することも可能です。手動指定する場合は、配信用と管理用に異なる32〜256文字のBearer対応ASCII値（英数字、. _ ~ + / -、末尾の=は最大2個）を使ってください。空白と引用符は使えません。

payload_bytes_sent は、チャンク全体の書き込みとflushが成功したデータ本体の合計です。失敗したチャンクの途中まで書き込まれたバイトは含まれず、TCP受信確認やクライアントの受信完了も示しません。

設定JSONと管理者用JSONは、同じオブジェクト内で大文字・小文字を区別しない重複キーがあると起動時に拒否されます。どの値が有効か曖昧な設定でサーバーが起動するのを防ぎます。

**検証クライアントは `curl --max-time 3` などで短時間で切断してください。** これは受信側のテスト制限であり、サーバーの配信上限ではありません。ヘッダーは全体で10秒、無通信では5秒で打ち切ります。送信停止時も5秒で切断しますが、いずれも通常配信の総時間を制限するものではありません。

既存Web環境に配置する際は、隔離された認証付きデコイ経路からリバースプロキシで中継します。直接バックエンドへ中継する場合は`127.0.0.1:9080`を指定します。付属の認証付きNginx例を使う場合、同一ホストのTLSゲートウェイはNginxの`127.0.0.1:9082`へ接続し、Nginxからバックエンドの9080へ転送します。別ホストのゲートウェイでは、NginxをプライベートIFにだけ束縛し、接続元をそのゲートウェイに限定するファイアウォールを設定してください。各中継区間のTLS、バッファリング・圧縮の無効化、タイムアウトを確認します。`/stop` と `/health` は外部へ中継せず、管理用トークンを配信用に渡さないでください。GUIからのサーバー起動・公開、本番ログインとの連携、通知・イベント履歴の保存は含みません。詳しくは生成ZIP内のREADMEも参照してください。Nginxのread/send timeoutは無通信間隔の制限で、総配信時間の上限ではありません。ただし、CDNやゲートウェイに別の絶対応答時間上限があれば切断されるため、実経路で確認してください。

付属のNginx JSONアクセスログは時刻・メソッド・パス・状態・転送量・所要時間・リクエスト制限状態（`rate_limit_status`）を記録しますが、接続元IPと認証IDは記録しません。`DELAYED` はリクエストが制限により遅延されたことを示します。`request_seconds` は応答全体の所要時間で、制限による遅延時間だけではありません。早期検知にはゲートウェイのリクエスト開始ログを使ってください。接続元の帰属が必要なら、信頼済みゲートウェイで必要最小限の識別子を記録し、アクセス制限と保持期間を設定してください。任意の転送ヘッダーは信用しないでください。

### ディレクトリ・メイズ

設定キー、有効な環境用URL、環境名、両方のコメントを編集できます。環境名は `APP_ENV` と既定URLのホスト名に反映されます（例：`staging` は `staging.example.invalid`）。URLを手入力する場合も選択した環境に合わせてください。開発環境の既定URLは `http://dev.example.invalid:8080` です。生成前に詳細設定の有効URLやコメントを確認してください。`example.invalid`以外のホストを入力する場合は、所有し、本番認証のない隔離検証先だけに向けていることをチェックで確認してください。URLをたどるクローラーやAIエージェントからリクエストを受ける可能性があります。生成器は名前解決・接続を行いません。内部・本番の接続先は使わないでください。確認は設定ファイルに保存されず、設定読込後は改めて必要です。通常形式で使う「URLを記載する文脈」の項目名や表示文言は、この形式には適用しません。発行されたカナリアURLを変更せず、値を引用符で囲みます。シェル展開につながる文字や改行を含む入力は受け付けません。

暗号化ネスト、ディレクトリ・メイズ、エンコーディング・メイズでは、顧客管理・移行・保管・カード台帳・企業一覧・認証情報保管庫・請求・従業員・取引先・受注・サポートチケット・IT資産・API認証情報台帳・クラウド資産のシナリオを選べます。既存のデータベース雛形12種類と同じ合成スキーマを使い、ファイル名・資料名・URLの用途をシナリオに合わせます。カード番号は決済に使えない参照値で、PANやCVVは生成しません。認証情報保管庫も架空の値だけを使います。認証情報保管庫ではlogin_url、API認証情報台帳ではapi_endpointの1行にカナリアURLを入れられます。カナリアURLを指定すると、`.env` 以外の候補ファイルでは、架空 `login_url` または `api_endpoint` レコードの値をURLに置き換えます。`.env` ではシナリオに対応する環境変数にURLを置きます。`password` などの認証情報は置換しません。URLを置いたレコード番号・項目名・ファイルパスは管理者専用台帳に記録します。暗号化ネスト内の文書名と分岐ZIP名は、シナリオ別の業務用語彙から修飾語を分散させて選び、連番名を避けます。`.env` は開発用設定とコメント化した本番用カナリアURLを含みます。既定の `example.invalid` は安全な仮値である一方、見破る手掛かりにもなります。配置前に運用環境に合わせて確認してください。URLはアクセスされて初めて通知され、ファイルの取得だけでは通知されません。

階層1〜6、分岐1〜5、各ディレクトリのダミー1〜3件、全ファイルに共通する1形式、相互リンクの有無を設定します。ルートを含め最大400ディレクトリ・生成内容と配置用ZIPは各16MiBまでです。フォルダー名は複数の業務領域から選び、同階層で重複せず、隣り合う階層では同じ名前を避けます。一覧にはフォルダーに応じた見出し・パンくず・短い説明を付けます。タイトル欄を空にすると、選択したシナリオのタイトルを使います。ZIPを隔離した静的配信領域に展開し、ルートの `index.html` を入口にします。全ページに子ディレクトリとダミーへのリンクがあり、相互リンクを有効にすると親・別枝への経路も追加します。カナリアURLを1行ずつ指定するとダミーに割り当て、管理者専用台帳にパスとの対応を記録します。認証情報保管庫シナリオでは、URLを入れた `login_url` のレコード番号と項目名も台帳に記録します。

`.env`を選ぶと、生成された隠しファイルが配信基盤の既定ルールで拒否される場合があります。隔離したデコイ領域だけで取得できることを確認してください。デコイを見せるために隠しファイル保護を全体で解除したり、本物の設定ファイルを公開したりしないでください。

循環はHTMLリンクで作り、ファイルシステムのシンボリックリンクは使いません。構造は有限で、URLを重複排除する探索では同じページの巡回が打ち切られます。効果は無限巡回の保証ではなく、候補探索・取得・選別の追加作業として検証します。アクセス監視は配信側で設定してください。

静的デコイの配信には `examples/nginx-decoy.conf` を使えます。送信元ごとに毎秒5件、バースト10件までを許可し、超過分はHTTP 429で拒否します。制限で遅延したリクエストは `rate_limit_status: DELAYED` として記録します。`request_seconds` は応答全体の所要時間で、制限による遅延時間だけではありません。Nginxの前段にゲートウェイがある場合は、設定済みの信頼済みプロキシからだけ接続元IPを受け取ってください。設定を誤ると、利用者がゲートウェイの同じ制限枠を共有したり、接続元IPを偽装されたりします。これは毎分10件・バースト5件のインフィニット・ストリーム用Nginx例とは別の設定です。

### エンコーディング・メイズ

用途シナリオ、候補1〜20件・変換1〜8階層、Base64、Base64url、Hex、パーセントエンコード、Gzip＋Base64の組み合わせ、復元後の形式を指定します。生成内容と配置用ZIPは各16MiBまでです。候補ごとに独立した架空レコードを生成し、ファイル名・タイトル・スキーマを選択した業務に合わせます。ZIP内のファイル順と `index.json` の候補順はランダム化し、管理者専用JSONにはシナリオ・復元順序・SHA-256を記録します。認証情報保管庫を選ぶと、.env以外の候補ファイルでは架空login_urlレコードにカナリアURLを置き、password値は変更しません。

各層は `encoding` と `payload` を持つJSONです。`encoding` に従って `payload` を復元し、JSONの層を剥がすと元のファイルになります。Gzipを使う層のヘッダー日時は生成時点から過去180日以内で変化し、元ファイルの履歴を示しません。管理者用JSONには候補ごとの復元順序・復元後の形式・SHA-256を記録します。暗号化ではなく、一括復元は可能です。候補の比較や内容確認に要する作業を評価するサンプルです。カナリアURLを1行ずつ指定すると候補ごとに割り当て、管理者専用台帳に対応を記録します。エンコードされたデータを読むだけでは通知されません。

## 現在の制限

- GUIと生成処理はローカルPC上で動作します。サーバーは `127.0.0.1` にのみ待ち受けます。同一ユーザーの別プロセスを含むローカル端末自体の侵害は防げません。
- スタティック・デコイ・ポータルは静的HTMLです。本番認証との連携、設定変更の状態保持、アクセスログ、カナリア受信・通知は未実装です。インフィニット・ストリームは独立した検証用サーバーとして提供します。
- 実システムへの自動配置、クラウド連携、インストーラー、自動失効は未実装です。管理台帳JSONを出力し、配置先の記入・撤去は利用者が行います。
- 文書はテンプレートと架空データから生成します。本物との識別不能性や、読んだだけでのカナリア通知を保証するものではありません。

### 騙しと遅滞の評価

許可された演習で、本物の機密情報の代わりに模擬ターゲットを配置し、対策あり・なしを同じ初期情報と制限時間で比較してください。AI、スクリプト、並列・オフライン処理も想定し、到達率、到達した場合の時間、カナリア接触、通知、対応時刻と正規利用の誤検知を記録します。演習結果の集計例は次のコマンドで確認できます。

```bash
python examples/evaluate_deception.py examples/deception-evaluation-sample.json
```

実験条件の記録には、連携サンプルの `examples/deception-study-metadata-template.json` を使えます。必須欄は空欄の雛形なので、条件を記入してから完成版を検証してください。JSON Schemaは必須説明欄の空文字、上限を超える長さ、重複するツール名・テレメトリ項目を拒否します。付属CLIは空白だけの必須欄も拒否します。連携サンプルには標準ライブラリだけで動く、2 MiB上限の検証スクリプトも含まれます。試行イベントの入力JSONとは分けて保管し、実資格情報、カナリアURL、本番情報、個人情報は記載しないでください。完成したメタデータの検証:

```bash
python scripts/check_study_metadata_schema.py path/to/study-metadata.json
```

引数なしで実行すると、空欄のスターター雛形の構造だけを確認します。完成記録としての必須欄チェックは、ファイルを指定した場合に行います。

このサンプルは正規利用者のデコイ接触でアラートが出る例を1件含みます。出力される割合や区間は説明用で、実測の誤検知率ではありません。実験条件の入力形式は [`examples/deception-study-metadata-template.schema.json`](examples/deception-study-metadata-template.schema.json)（JSON Schema Draft 2020-12）で検証できます。

攻撃者群の集計では、囮接触が模擬秘密より先だった試行、囮接触なしまたは秘密到達が先だった試行、秘密に届かず制限時間を迎えた試行を分けて表示します。同じ時刻に記録された囮接触と秘密到達は順序不明として `simultaneous_decoy_contact_and_secret` に別集計し、接触が先だった試行には数えません。囮接触から秘密到達までの中央値は、接触後に秘密へ到達した試行だけの値です。未到達試行の接触後時間は右打ち切りとして別集計し、実測遅延には数えません。対照群では `decoy_time` を `null` にしてください。

攻撃者群には、Kaplan–Meier法による秘密到達時間の中央値と、各群の最短試行期限までの「秘密未到達時間」の制限平均も出します。両群の試行期限が同じ単一値なら、囮群−対照群の制限平均差も出し、正の値はその期限内で囮群の方が秘密未到達時間が長かったことを示します。群は対応付けられていない記述値であり、囮が遅延を引き起こした証明にはなりません。

この生存分析は、期限による打ち切りが秘密到達時間と独立していることを仮定します。攻撃者の進行状況を見て試行を途中終了した場合、この仮定が崩れる可能性があります。推定曲線が期限内に0.5へ達しなければ、Kaplan–Meier中央値は `null` です。
出力JSONの `schema` は `adg-evaluation-v10` です。各群にはデコイ接触・アラート・対応の `event_time_medians_seconds_when_observed` に加え、`ordered_latency_pairs` と `ordered_latency_medians_seconds` でデコイ接触からアラート、アラートから対応までの時間も出します。後者は両方の時刻が記録され、後のイベント時刻が厳密に大きい試行だけを対象とします。同時刻・逆順の組は遅延中央値から除外し、`nonpositive_latency_pairs` に件数を出すため、イベント順序や記録の不整合を確認できます。対象件数を確認してください。いずれも条件付きの記述値であり、生存分析の推定値やデコイが通知・対応を引き起こした証明ではありません。

集計結果では、各群の到達率にWilson法の95%信頼区間を、対照群との差にNewcombe法の95%信頼区間を表示します。少数試行では区間が広くなり、信頼区間だけで因果関係や有効性は証明できません。
正規利用者の通常動作による基準と、デコイ設置後の誤通知・接触を比べるため、authorized の control と decoy の両方を記録してください。どちらかが欠ける場合、集計スクリプトは不足を警告します。
サンプルは架空の数値であり、有効性の実測結果ではありません。JSONの `runs` に `actor`（`attacker` または `authorized`）、`arm`（`control` または `decoy`）、`budget_seconds`、任意の `secret_time`、`decoy_time`、`alert_time`、`response_time` を開始からの秒数で記録します。未到達の試行で予定より早く観測を終えた場合、`budget_seconds` には予定上限ではなく実際の観測終了までの時間を記録します。予定最大時間はメタデータ雛形に別途記録してください。未発生は明示的に `null` とします。時刻欄を省略した場合も計算上は `null` と同じですが、出力の各群にある `omitted_event_fields` で欄ごとの省略件数を確認できます。省略は「未記録」であり「イベント未発生」の証明ではありません。正規利用者（authorized）の試行ではsecret_timeを必ずnullにします。重複キーのあるJSONは曖昧な入力として拒否します。試行レコードに仕様外の項目がある場合も拒否し、時刻名の誤記を未到達として黙って集計しないようにします。各群でアラート時刻がある試行の割合とWilson法の95%区間を出します。`alert_rate_comparable_within_group` が `false` の場合、その群は試行時間が混在しており率の単純比較に適しません。正規利用者群の割合は誤検知の候補指標です。アラートが正規利用に起因するかを確認してから誤検知として解釈してください。これは試行単位の割合で、同一試行中の複数アラート数は数えません。両群が同じ単一予算の場合、`attacker_comparison` にデコイ群−対照群の到達率差を出します。到達時間の中央値差は到達した試行のみの比較で、未到達試行を含まず選択バイアスがあります。群は対応付けられていない記述的な比較であり、因果効果を証明しません。対応が先に記録されても、漏えいを防いだ証明にはなりません。このスクリプトは集計のみを行い、攻撃や通知は実行しません。 最上位JSONは `runs` 項目だけを受け付けるため、実験条件などのメタデータは別ファイルに記録してください。
この集計入力には、シナリオの同等性、割付方法、AIモデル、使用スクリプト、並列数、開始時に与えた情報を記録しません。これらを条件間で揃え、機密情報を含めず別の実験記録に残してください。集計結果は条件差を補正できません。
